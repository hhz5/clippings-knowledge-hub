我用2小时，做了个让AI自动剪视频的工具。

银海inhai AI视频剪辑产品开发智谱AI提示词 2025-12-15

让AI帮忙看完视频自动剪辑一气呵成。

原创 银海 2025年12月15日 11:04

Hi，我是银海。

不知道大家在整理录过的一些视频素材时，有没有遇到这样的问题： 长视频里总有那么几个精彩片段，但它们散落在各处。

每次都得拖着进度条一点点找，找到还得记时间点，再切到剪辑软件里手动剪，费时又费劲。

既然现在AI已经能“看懂”视频了，那有没有可能让它帮我把关键片段自动挑出来，我只需要点几下就能导出成品？

带着这个想法，我花了两小时左右把这个工具做了出来，看下面这个视频：

整个工具的逻辑不复杂，流程大致分三步：

上传视频文件，先让AI分析视频内容，找出值得剪的片段，然后我在界面里挑选想要的部分，最后后台自动剪辑并导出。

但是真正做起来时，细节比想象得多，踩坑也不少， 下面就一步一步分享我是怎么搭建出这个应用出来的吧。

工具的实现过程中，最大的问题来自于“让AI看到视频”，然后分析出不同的时间片段并分析出为什么，这对于视觉模型的基础能力来说就非常关键。

我本次用的是智谱最新开源的 GLM-4.6V 视觉模型，之前看一些宣传参数里说明，GLM-4.6V 在 MMBench、MathVista 等 30+ 评测中表现优异，128k 上下文（约等于 150 页文档或 1 小时视频），支持“过目不忘”的长视频理解和多文档分析 。

之前在演示视频里面直接输入主题或论文，自动检索配图、审核图片质量，生成图文并茂的公众号/研报内容，还是比较让我好奇心动，所以选择它作为本次的选手。

而前段时间趁低价购买的最低只要20元/月的GLM Coding Plan正好跟本次的 GLM 4.6V 结合就是本次的工具构建的最佳拍档，体验链接：https://www.bigmodel.cn/claude-code?ic=XOPPYZLH2M

关于如何在Claude Code、Cursor、Cline中使用GLM 4.6在这里就不逐步配置说明了，感兴趣的朋友可以直接看这份教科书级的官方文档说明：https://docs.bigmodel.cn/cn/coding-plan/overview

现在万事俱备了，我们就展开讲讲如何实现。

开局直接输入一个需求，你可以是一个模糊的需求，然后先能够表达出整个实现逻辑，我这里是直接用语音输入的，即便有一些字样出现了混乱，但是智谱GLM4 4.6依旧能够很好的理解我的诉求，然后先帮我设计架构图：

我想做一个能够上传视频后识别视频中的一些精彩片段，并进行自动剪辑。我会提供具备多模态视频理解的大语言模型 API。我需要你帮我做的是根据识别出来的这个结果，然后进行视频片段的这个剪辑，然后我需要一个前端的页面，然后后端处理使用拍摄。请你帮我设计一整个架构信息，然后我喜欢使用简约风格的设计，请你可以使用 tailwindcss 的 CSS 样式作为前端的这个规范。

前端用的是 TailwindCSS，布局参考了剪映： 左边是片段列表，中间是视频预览区域，右侧显示AI分析出来的片段信息，而实现方式也是非常的简单粗暴。

因为我们选用的 Coding Plan 里面有具备 GLM 4.6 V模型 的工具调用能力，我如果想要调整 UI 只需要截个图进去传入即可。

我传入的图实际上就是这么一张图，然后简单的一句话，因为它能够很好地看懂你想要的布局信息。

对我而言，深色主题，看起来更舒服一些。

后端用 Python ，主要是它底层还是有使用FFmpeg这个包。而我们所需要使用到的两个其他的后端服务，一个是视觉分析的能力API（GLM 4.6V），还有一个是将上传的视频转成公网OSS地址的服务能力，直接给GLM 4.6 说读取我们提供的相关接口文档即可。

你可以直接去智谱的官网，把GLM 4.6V 的相关文档直接贴给对话窗里面即可，依旧简单粗暴。

参考文档地址：https://docs.bigmodel.cn/api-reference/

在我们测试运行中发现，因为我们的视频是存在本地的，为了能够让GLM-4.6V能够读取我们的视频，我们需要有一个让视频能够在公网上可以访问的地址。

最后实现的是： 用户上传 → 后端自动推到 OSS → 获取 公网 可访问的地址 → 发给 GLM-4.6V 分析 → 返回结果渲染。

所以用了阿里云的OSS对象存储，然后就可以给到GLM-4.6V去使用这个上传后返回的视频链接。

而至于如何对接以及获取对应的密钥信息，这些都直接问 GLM-4.6 就能搞定，它的本身训练数据里面，已经有了相关产品的对接信息，它在整个代码生成过程中，只需要我们把鉴权信息和OSS Bucket地址一贴就完事。

甚至在追问的过程中，你可以直接把一些报错给到GLM-4.6，它会很细心教你如何设置相关的权限信息。

在整个过程中，真正花时间最多的不是写代码，而是调提示词，下面把我的提示词分享给大家供参考。

一开始我让AI“找精彩片段”，结果它给出的分析完全泛化，什么“画面清晰”“内容丰富”这种毫无参考价值的判断。

我后来换了一种提法，不说“精彩”，改说“爆点”，就是那种让人愿意停下来、愿意分享的片段。

提示词里加了很多具体标准，比如有没有情绪爆发、有没有金句、有没有反转、适不适合做短视频开头，并且特别强调宁缺毋滥，分数低于0.7的不用给我。

这样调整之后，AI的判断明显靠谱了不少。

它不仅告诉我哪个片段值得剪，还会给出原因，是节奏变化、情绪高潮，还是一句话特别有传播力，这些都让筛选过程更有参考意义。

现在这个工具我自己用得挺舒服。

录一个几十分钟的视频，上传后让AI分析一下，几分钟就能把值得剪的片段全部标出来，点几下就能生成成品。效率比以前手动找片段快太多， 而且最后剪辑出来的片段，我对它的期待是宁缺毋滥，只希望有高质量的结果输出。

如果你正在做类似的事情，或者想学习如何把AI能力整合到自己的工具里，这个项目或许能给你一些参考。

然后如果你如果还没有找到合适的编程工具和基础模型的话，直接上这个 Coding Plan 就完事了，一整套方案开箱即用，性价比极高。

AI 的能力越来越强，但它依然是工具，关键是先把自己的需求想清楚，再决定让AI接手哪一步。

对我来说，这个工具最省时间的地方并不是“剪辑”，而是“找片段”。

AI帮我把最机械、最耗时的部分自动化了，而怎么剪、剪哪段，最终决策仍然在我手里。

人机协作，各做各的强项，大概才是我认为的把AI真正用好的方式。
