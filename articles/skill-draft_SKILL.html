SKILL

skill-draft 2026-04-15

内容写作统一器

目的

把 AI / 工具 / Prompt / Skill / 工作流 / 效率主题加工成稳定、可发布、图文一体的中文内容资产。

目标不是单纯写一篇文章，而是同时产出：

  • 有点击欲的标题
  • 有阅读动力的开头
  • 有结构和判断的正文
  • 可复制的模板 / Prompt / 清单 / SOP
  • 与正文强绑定的配图规划
  • 自然可用的 CTA

何时触发

当用户出现以下意图时触发本 Skill：

  • 想写公众号文章
  • 想写小红书长文 / 图文笔记
  • 想把一个主题写成实用内容
  • 想把 Prompt / Skill / 工作流包装成内容
  • 想做测评、教程、玩法盘点、工作流拆解、观点解读
  • 想让内容更有网感、更有结构、更适合传播
  • 想让文章自带配图规划
  • 想把内容写作流程沉淀成统一模板

典型触发词：

  • 写篇文章
  • 帮我整理成公众号
  • 帮我写成小红书
  • 给我一个内容写作 prompt
  • 帮我做成教程
  • 帮我写成 Prompt 分享文
  • 帮我做成工作流拆解
  • 帮我写成测评

不适用场景

以下场景不要强行使用本 Skill：

  • 纯新闻快讯，不需要结构化深加工
  • 纯学术论文摘要，不强调传播性
  • 纯品牌广告文案，不需要实操内容
  • 纯短句海报文案，不需要长文结构
  • 单纯润色已有完整文章，而不需要重构

如果用户只是要一句标题、几句 slogan、一个微博短贴，应使用更轻量的写作流程，而不是完整 Skill。

核心原则

1. 不是解释清楚，而是交付价值

输出必须让读者：

  • 愿意点开
  • 愿意读完
  • 觉得有收获
  • 愿意收藏
  • 愿意动手试

2. 内容必须有结构

不能输出散乱信息堆砌文。 必须先判断内容类型，再套对应骨架。

3. 内容必须可复制

正文里至少要给出一种可以直接拿走的东西：

  • Prompt
  • 模板
  • 清单
  • SOP
  • 步骤
  • 参数建议
  • 对比标准

4. 图文必须一体

配图不是最后补的装饰，而是正文的一部分。 正文推进到哪里，图片就应该承接到哪里。

5. 风格要稳，不要每次一个味

必须根据平台、人设、语气偏好、内容目标决定风格组合。

6. 禁止正确废话

避免以下问题：

  • 空泛趋势
  • 套话堆砌
  • 背景过长
  • 没有结论
  • 没有案例
  • 没有模板
  • 没有适用边界

使用流程

第一步：读取输入并补全任务

先识别以下字段，缺少时按合理默认值补足：

  • 主题
  • 目标读者
  • 发布平台
  • 内容类型
  • 账号人设
  • 语气偏好
  • 判断力度
  • 节奏密度
  • 内容目标
  • 想重点讲的工具 / 产品 / 方法
  • 核心结论
  • 已有素材
  • 已有截图 / 配图素材
  • 是否需要补配图规划
  • 希望读者看完后做什么
  • 是否需要文末可复制模板
  • 是否需要评论区互动话术

第二步：判断内容类型

从以下类型中选择一个主类型：

  • 教程指南型
  • 实测测评型
  • 工作流拆解型
  • Prompt / Skill 分享型
  • 玩法盘点型
  • 观点解读型

不要混用多套骨架。 如果用户已指定内容类型，优先服从；否则根据主题自动判断。

第三步：确定风格组合

风格必须按四层确定：

  1. 表达温度
  • 克制理性
  • 专业清晰
  • 作者感
  • 强网感
  • 兴奋外放
  • 闺蜜分享
  • 冷幽默
  • 观察者视角
  1. 判断力度
  • 保守表达
  • 中等判断
  • 强判断
  1. 节奏密度
  • 稍慢
  • 中速
  • 快节奏
  1. 内容野心
  • 信息传达型
  • 实用教程型
  • 方法论沉淀型
  • 爆款传播型
  • 资源领取型

执行规则：

  • 只选 1 个主风格 + 1 个辅助风格
  • 只选 1 个主目标 + 1 个副目标
  • 平台优先级高于个人发挥

默认推荐：

  • 公众号：专业清晰 + 作者感；中速；方法论沉淀型 + 信息传达型
  • 小红书：强网感 + 闺蜜分享；快节奏；爆款传播型 + 资源领取型
  • Prompt分享：专业清晰 + 作者感；中速；资源领取型 + 方法论沉淀型
  • 测评/工作流：专业清晰 + 轻微兴奋；中速偏快；实用教程型 + 信息传达型

第四步：选择正文骨架

A. 教程指南型

  • 开头钩子
  • 为什么值得学 / 适合谁
  • 准备工作
  • 步骤拆解
  • 常见问题 / 踩坑提醒
  • 最终结果
  • 可复制指令 / 清单 / 模板

B. 实测测评型

  • 开头钩子
  • 为什么测这个
  • 测试标准
  • 测试过程
  • 每个选项的表现
  • 最终结论
  • 适合谁 / 不适合谁
  • 推荐用法

C. 工作流拆解型

  • 开头钩子
  • 场景和目标
  • 输入是什么
  • 中间处理过程
  • 输出结果
  • 完整流程拆解
  • 效率提升点
  • 模板 / Prompt / SOP

D. Prompt / Skill 分享型

  • 开头钩子
  • 解决什么问题
  • 旧方法为什么不稳定
  • 核心设计思路
  • 模块拆解
  • 适用场景
  • 不适用场景
  • 使用方法
  • 示例输入输出
  • 完整模板

E. 玩法盘点型

  • 开头钩子
  • 为什么这个方向值得玩
  • 最值得试的几个玩法
  • 每个玩法的场景 / 效果 / 难度 / 提示词
  • 哪几个最值得先试
  • 一句话总结
  • 模板 / 指令 / 资源

F. 观点解读型

  • 开头钩子
  • 先抛出核心判断
  • 为什么很多人理解错了
  • 我为什么这样判断
  • 拆解逻辑
  • 案例 / 反例
  • 可执行建议
  • 总结收束

第五步：同步规划配图

必须在写正文时同步规划图片，不允许最后补图。

每张图都必须承担至少一个职责：

  • 吸引点击
  • 展示效果
  • 证明作者实测过
  • 解释步骤
  • 展示前后对比
  • 总结信息
  • 提供可截图收藏的模板

图片分布规则：

开头配图

优先：

  • 最终成品图
  • 最强效果图
  • 对比图
  • 结果展示图

中段配图

优先：

  • 步骤截图
  • 工作流图
  • 对比图
  • 案例图
  • 局部细节图

结尾配图

优先：

  • 总结图
  • 模板卡片图
  • Prompt 卡片图
  • 一页清单图

图片优先级：

  • 高信息密度图 > 氛围图
  • 结果图 > 抽象意象图
  • 对比图 > 单张展示图
  • 模板图 > 装饰图

每张图都要输出：

  • 位置
  • 用途
  • 建议形式
  • 画面内容
  • 图注重点

至少规划 6 张图。 长文建议 8-10 张。

第六步：生成完整输出

输出顺序固定为：

  1. 本文采用的内容类型
  2. 本文采用的风格组合
  3. 标题备选（12个）
  4. 一句话摘要（3个）
  5. 导语 / 开头钩子（3个）
  6. 正文
  7. 文末可复制资产
  8. 配图规划
  9. CTA 备选（5条）

如果用户明确要求评论区互动话术，再附加：

  • 评论区互动话术（5条）

标题规则

标题必须具备点击欲，但不能低质标题党。

优先组合以下元素中的 2-4 个：

  • 数字
  • 工具名 / 产品名 / 方法名
  • 具体场景
  • 明确收益
  • 第一人称“我”
  • 第二人称“你”
  • 反差
  • 附资源（附提示词 / 附模板 / 附教程）
  • 问句或惊叹感

高频标题逻辑：

  • 我测了 X 个___，终于找到___
  • 别再___了，真正有用的是___
  • 保姆级教程：从 0 到 1 跑通
  • 真正的杀手级用法，竟然是
  • 我把___全试了一遍，给你一份能抄的作业
  • ___火了，但大多数人都没用对

禁止：

  • 平铺直叙标题
  • 内部汇报感标题
  • 像说明书一样的标题

开头规则

前 3 段必须完成：

  1. 快速切入
  2. 建立阅读理由
  3. 明确交付承诺

可选切入方式：

  • 热点事件
  • 个人经历
  • 用户痛点
  • 常见误区
  • 先说结论

禁止：

  • 一上来定义概念
  • 一大段背景科普
  • 空泛行业趋势
  • 没有场景、没有问题、没有承诺

正文要求

必须做到

  • 每段尽量只讲一个核心点
  • 每部分都要有存在价值
  • 多用步骤、清单、模块、示例、对比、结论句

如果提到工具

必须回答：

  • 它到底牛在哪
  • 它适合谁
  • 它什么时候不值得用

如果提到 Prompt

必须回答：

  • 为什么这么设计
  • 怎么喂输入
  • 怎么判断输出是否合格

如果提到工作流

必须回答：

  • 输入是什么
  • 中间处理怎么走
  • 输出是什么
  • 哪里最容易出错

如果提到教程

必须回答：

  • 从哪里开始
  • 哪一步最关键
  • 哪一步最容易翻车
  • 最终效果是什么

失败兜底层

在输出最终内容前，必须检查以下失败模式；一旦出现，先修正再输出。

A. 标题失败

表现：

  • 像日报、周报、说明书
  • 没有结果承诺
  • 没有场景
  • 没有点击欲

修正：

  • 增加收益、反差、数字、资源钩子

B. 开头失败

表现：

  • 前 3 段还没进入问题
  • 还没告诉读者为什么值得看
  • 背景铺垫过长

修正：

  • 重写开头
  • 前置经历 / 热点 / 误区 / 结论

C. 内容空心化

表现：

  • 只有正确的话，没有步骤、模板、案例、清单
  • 读者看完不知道怎么做

修正：

  • 增加至少一个可复制模块
  • 增加至少一个具体场景
  • 增加至少一个明确动作建议

D. 结构失焦

表现：

  • 内容类型和骨架不匹配
  • 教程写成观点文
  • 测评写成介绍文
  • Prompt 分享写成工具介绍

修正：

  • 回到内容类型路由
  • 按对应骨架重组

E. 判断太弱

表现：

  • 没有明确结论
  • 大量模糊表达

修正：

  • 增加一句主判断
  • 每部分补一句最重要结论

F. 判断过猛但无支撑

表现：

  • 结论大，但没有案例 / 体验 / 对比

修正：

  • 增加证据和限定范围

G. 图文割裂

表现：

  • 正文讲很多，但图片没承接
  • 配图只是装饰

修正：

  • 重新规划配图位置、用途和图注重点

H. 结尾虚弱

表现：

  • 只有“以上就是分享”
  • 没有收束
  • 没有 CTA

修正：

  • 增加强收束
  • 明确最值得记住的一点
  • 给出自然 CTA

I. 平台不匹配

表现：

  • 小红书写成公众号
  • 公众号写成碎片口播稿
  • Prompt 分享写成情绪短文

修正：

  • 回到平台适配规则，重写段落长度、语气、CTA、图文比重

J. 没有账号感

表现：

  • 结构对，但语言没有人格

修正：

  • 回到风格层，强化措辞、判断方式、图注语言、CTA 风格

强制自检

输出前逐项确认：

  1. 内容类型是否明确
  2. 风格组合是否明确
  3. 标题是否至少有 3 个真的可用
  4. 开头是否在前 3 段内建立阅读理由
  5. 是否至少有 1 个可复制模板
  6. 是否至少有 1 个适用边界说明
  7. 是否至少有 1 个明确主结论
  8. 是否至少有 6 张图的规划
  9. 每张图是否有明确用途和图注重点
  10. 结尾是否有强收束和 CTA
  11. 是否避免空洞套话
  12. 读者看完后是否知道下一步怎么做

如果有任意一项不满足，继续优化后再输出。

平台适配

公众号

  • 结构完整
  • 信息密度高
  • 段落适中
  • 适合方法论沉淀
  • 可略带观点升华

小红书

  • 开头更快
  • 段落更短
  • 更强调痛点、结果、收藏点
  • 更适合卡片图、清单图、截图图

社媒长帖 / 即刻 / 朋友圈长文

  • 节奏更快
  • 更像个人经验分享
  • 少铺垫
  • 更多结论句和判断句

如果未指定平台，默认：

  • 公众号结构
  • 加一点小红书友好表达
