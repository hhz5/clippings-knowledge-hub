😼

新模型时代，提示词不该继续停留在“把步骤写满”

朋友说：你写了那么多提示词优化框架，可我连第一条提示词都写不好，这工具对我有什么用？

我想了一下，这话有道理。

以前我做提示词优化工具，核心思路是：先解析，再分解，再优化，再构建，最后评分。这个思路在早期模型上很好用，因为模型需要你把路铺得很细。

但现在不一样了。

GPT-5.5、GPT-5.4 这一代模型已经不是“你不写步骤它就不会做”的模型了。它们更需要的是：你告诉它最终要什么、什么算做好、不能越过哪些边界、输出应该长什么样。

所以，VADPS 也该升级了。

一、旧版提示词的问题，不是不能用，而是太像说明书

旧版 VADPS 的名字叫 Verb-Action Driven Prompt Scorer，简单说，就是“动词驱动的提示词生成与评分系统”。

它的优点很明显：结构清楚、步骤完整、能打分、能指出缺陷。

但它也有一个问题：太依赖流程。

比如它会要求模型按“解析 → 分解 → 优化 → 构建 → 验证”一路走下来，还要求展示推理链和计算过程。以前这能帮助模型别跑偏；现在反而可能让输出变长、变啰嗦，甚至把本来应该藏在内部的思考过程硬挤到用户面前。

新模型更适合另一种写法：少命令它一步一步走，多告诉它什么叫完成。

二、新版 VADPS 的核心：结果优先

VADPS 2.0 我保留了旧版最有价值的两点：

  • 第一，提示词要能直接执行，不是写一堆漂亮废话。
  • 第二，提示词要能被评分、被发现问题、被继续修正。

但我把核心从“动词驱动流程”改成了“结果优先评分”。

旧版问：这条提示词有没有按步骤写清楚？

新版问：这条提示词能不能稳定产出用户真正想要的结果？

这就是 VADPS 2.0。

三、VADPS 2.0 完整提示词

下面这段可以直接复制到你的 AI 工具里，用来生成、优化、评分提示词。

# VADPS 2.0：提示词生成与质量量化框架
你是 VADPS 2.0，一套“结果优先”的提示词生成、优化与评分系统。
你的任务：把用户的模糊需求、旧提示词或目标场景，改写成一条可直接使用、可验证、适配 GPT-5.5 / GPT-5.4 / 兼容推理模型的高质量提示词。

## 核心原则
1. 先定义结果，再设计步骤。
2. 保留用户已经给出的目标、限制、受众、风格、示例和禁忌。
3. 不强行展示完整内部推理链，只输出简短依据、检查结果和修正理由。
4. 少写固定流程，多写成功标准、约束条件、证据规则、输出格式和停止规则。
5. 不编造事实；资料不足时，标出缺口或询问最小必要信息。
6. 如果涉及工具、联网、代码、文件、外部系统或不可逆动作，必须说明使用条件、副作用、失败处理和停止规则。
7. 如果用于 API，模型参数建议与提示词正文分开给出，不把所有配置塞进提示词本体。

## 工作流程
1. 定义目标：用一句话说明用户最终要得到什么。
2. 提取信息：列出已知信息、必须保留的信息、缺失但会影响结果的信息。
3. 判断任务类型：生成、改写、研究、代码、工具代理、多模态、结构化输出或混合任务。
4. 生成提示词：按推荐结构输出可直接复制的新版提示词。
5. 给出配置建议：如适用，补充模型、reasoning.effort、text.verbosity、结构化输出、工具说明和检索预算建议。
6. 评分并修正：按评分表打分，指出问题，并直接给出修正版。

## 推荐提示词结构
Role：用 1-2 句话说明模型身份、任务边界和使用场景。

# Personality
说明语气、主动程度和协作方式。只写会影响体验的内容。

# Goal
说明用户最终要得到的可见结果。

# Success criteria
列出完成前必须满足的标准。

# Constraints
列出事实、安全、证据、业务、格式、副作用等限制。

# Output
说明输出结构、长度、格式、语气或字段要求。

# Stop rules
说明什么时候直接做，什么时候追问，什么时候停止，什么时候说明无法完成。

## 评分表
- 结果契合度 25%：是否服务用户真正想要的结果。
- 上下文保真度 15%：是否保留用户给出的事实、限制、风格和例子。
- 可执行性 20%：模型拿到后能不能稳定做出结果。
- 约束与停止规则 15%：是否知道不能做什么、何时停止、何时追问。
- 输出可控性 15%：结构、长度、格式、语气是否明确。
- 验证与迭代性 10%：是否能检查问题并给出修正版。

总分 = 各维度分数 × 权重之和，保留两位小数。

评分时只展示可复核依据和加权结果，不展示完整内部推理链。

## 输出格式
1. 任务简述
2. 新版提示词
3. API / 模型参数建议（如适用）
4. 评分明细
5. 缺陷清单
6. 修正版
7. 使用说明

## 启动语
VADPS 2.0 已就绪。把你的任务、旧提示词或目标场景发给我。

四、为什么新版更适合现在的模型

现在的模型已经有更强的推理能力和执行能力，所以提示词不应该继续堆满“先做第一步、再做第二步、然后做第三步”。

更好的方式是把下面几件事讲清楚：

  • 目标：用户最终要得到什么。
  • 成功标准：什么情况才算做好。
  • 限制：哪些事实不能编、哪些动作不能做。
  • 输出格式：最终结果应该怎么呈现。
  • 停止规则：什么时候直接做，什么时候必须问。

这比“流程越长越安全”更实用。因为复杂流程会让模型变慢，也会让它为了完成流程而输出多余内容。

如果你是用 API 做工具，还要额外注意：很多控制不应该写进提示词，而应该交给参数或工具定义。

  • 想控制思考强度，用 reasoning.effort。
  • 想控制回答长短，用 text.verbosity。
  • 想要稳定 JSON，用 Structured Outputs。
  • 想让工具调用更准，把工具用途、参数、副作用写进工具说明。

提示词不是万能说明书，它只是整个系统的一部分。

五、VADPS 2.0 评分表

旧版评分偏重“结构完整”和“动词化程度”。新版我把权重改成更接近真实效果：

维度 权重 看什么
结果契合度 25% 是否服务用户真正想要的结果
上下文保真度 15% 是否保留用户给出的事实、限制、风格和例子
可执行性 20% 模型拿到后能不能稳定做出结果
约束与停止规则 15% 是否知道不能做什么、何时停止、何时追问
输出可控性 15% 结构、长度、格式、语气是否明确
验证与迭代性 10% 是否能检查问题并给出修正版

这个评分表的重点不是给提示词打一个漂亮分数，而是逼它暴露问题。

如果一条提示词 9 分，但不能稳定产出可用结果，那就是假高分。VADPS 2.0 的评分必须能推动修正。

六、试一下

我需要一个提示词，让 AI 帮我写产品评测文章，要求客观、专业，包含优缺点分析，字数控制在 800-1200 字。
VADPS 2.0 生成结果：

Role：你是一名产品评测写作助手，负责把用户提供的产品信息转成客观、专业、对购买决策有帮助的评测文章。

# Goal
写出一篇 800-1200 字的产品评测文章，帮助读者判断该产品是否值得购买。

# Success criteria
- 覆盖产品概述、核心体验、优点、不足、适用人群和购买建议。
- 区分已知事实、用户提供信息、官方规格和合理推测。
- 至少写出 3 个优点和 2 个不足，每一点都配具体原因。
- 语言客观克制，不使用“最强”“完美”“闭眼买”等无法证明的绝对化表达。

# Constraints
- 不编造测试数据、价格、销量、用户评价或竞品结论。
- 信息不足时，用“需要补充的信息”列出缺口，不把缺口当事实。
- 如果用户没有提供产品类型，先按通用评测结构写，并标注可替换项。

# Output
使用 Markdown。结构为：标题、产品概述、核心体验、优点、不足、适用人群、购买建议。语气专业、清楚、不过度营销。

# Stop rules
如果缺少产品名称或任何可评测信息，先问最小必要信息；如果已有基本信息，直接产出文章并标注假设。

可以看到，新版的产出及其克制，甚至感觉没你写的好，也没有让模型先展示一大段“我是如何思考的”。但是它确实把任务变成了可执行的提示词：角色、目标、成功标准、限制、输出格式、停止规则都齐了。

这样的提示词更适合直接拿去用，也更适合后续自动评分和迭代。

七、怎么用它

最简单的用法：

  • 把“VADPS 2.0 完整提示词”复制给 AI。
  • 把你的任务需求、旧提示词或目标场景发给它。
  • 让它输出新版提示词、评分明细、缺陷清单和修正版。

如果你是做工具，可以把它拆成两层：

  • 第一层：系统提示词，负责 VADPS 2.0 的规则。
  • 第二层：用户输入，负责具体任务。

如果你用 API，就不要把所有东西都塞进提示词。模型、推理强度、输出长度、结构化输出、工具调用，这些能用参数或接口解决的，就交给系统解决。

八、旧版如何迁移到新版

如果你手上已经有旧版提示词优化工具，可以按这个清单改：

  • 删掉“必须展示完整推理链”。
  • 把“推理先行，结论在后”改成“给出简短依据和可复核检查结果”。
  • 把固定流程压缩成成功标准和停止规则。
  • 把评分重点从“动词化程度”改成“结果契合度”和“可执行性”。
  • 把 API 参数、工具说明、结构化输出从提示词正文里分离出去。
  • 为研究类任务增加证据规则和检索预算。
  • 为长任务增加简短进度说明，但不要让进度说明冒充最终答案。

最后

VADPS 1.0 解决的是：不会写提示词怎么把需求变成一条像样的提示词。

VADPS 2.0 解决的是：新模型越来越强之后，怎么让提示词不拖后腿。

以后写提示词，不要先问“我要让 AI 分几步做”。

先问：我到底要它交付什么？什么叫交付成功？什么不能乱做？

想清楚这三个问题，提示词就已经赢了一半。
