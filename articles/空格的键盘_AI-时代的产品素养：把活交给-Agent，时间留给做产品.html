产品经理这个岗位从面世以来，他的发展路线就很清晰：

  • 初级产品：会画原型、会写文档、跟得上需求节奏。
  • 中级产品：能独立负责业务模块、跨部门协作、扛得起核心指标。
  • 高级产品：懂商业模式、能制定产品战略、能找到 PMF。

直到 AI 来了。画原型、写文档的时间极大变少。

我自己两年前画一个弹窗原型、要2-4 小时。现在截一张图，说一句话，几分钟就好。，计文档也会跟着出来。

画原型、写文档的时间变少了，剩下的时间，用来做什么？

这是对产品经理这个岗位未来发展的提问。

弄清楚这个问题，我们就知道产品岗位如何变化，产品的能力该怎么培养了。

以前，有初级产品的岗位来做画图仔，是因为之前就有那么多的活来让他做，现在 Agent 都能画了，那要公司要初级产品来做什么呢？

这里面有个悖论。

画原型也好、写文档也好，这些是需要时间去磨练的能力。

初级阶段反复手搓原型的过程是在训练他对界面信息层次的感知、对用户交互路径的本能反应、对边界场景的敏感度。

也就是我们说的在培养“品味”

现在这个能力的"训练场"没有消失，而是被压缩了。

对一个产品新人不需要重头去学习拖拽组件、手绘原型。

AI 把每个人的起点都拉到了同一条线上。

不存在初级、中级、高级，甚至不存在产品经理，大家都可以用 Agent 制作自己的产品。

这篇文想聊清楚一件事，AI 时代的产品经理素养，到底怎么练。

下面就是我自己这一年用 AI 做 PM 工作的全套方法，提供一些硬技能必备的工具和方法。

从 3 个画原型的 Skill、到 5 种工具盘点、到我开源的 13 个 PM-Skill 库。

最后再来探讨开头那个问题：AI 省下来的时间应该用来做什么，以及"产品品味"这件事在 AI 时代怎么培养。

一、3 个画原型 Skill，先理解 Agent 能做到什么

讲工具之前，先讲我自己提炼的 3 个 Skill。

它们是我基于这一年实战总结出来的 Claude Code 工作流。

三个 Skill 解决同一类问题：把"想法变成可沟通原型"这条路上的距离压缩到极致。区别只在输出物形态：

image2proto：

截图进去，单文件 HTML 原型出来。

浏览器打开就能交互。Tab 切换、弹窗开关、筛选展开都是真实的。发给任何人都能直接用，不用装环境。适合会前 5 分钟出 Demo，老板说"下午开会先看看效果"，这个最快。

图片 2 画笔：

截图进去，可编辑的 Pencil 设计稿出来，旁边还附一份结构化设计文档。

Pencil 是最近火起来的、专门给 Agent 用的设计工具。AI 出 80%，人在 Pencil 里改 20%。适合需要精细化交付的场景，B 端表单、多状态设计稿都靠这个。

制作原型示例：

url2proto：

网址进去，完整的 Next.js + Tailwind 本地项目出来。

AI 自己抓页面结构、设计 token、组件层级，自己规划项目架构，初始化项目，配置 Tailwind，拆组件还原。中间遇到样式对不上，它自己对比修。

一个网址，半小时出来一个能本地跑、能改、能持续迭代的工程化项目。适合多页面、大型项目、新产品原型起步。

技能地址：github.com/zephyrwang6/pm-skills

这三个 Skill 用下来，最大的体感让你重新理解"原型"这件事

原型制作就是一个对话过程。

截图、口头描述、AI 出稿、再口头改，这个循环跑十次的成本，比你手动画一稿还低。

你脑子里那个模糊的需求，可以在十几分钟里被反复显形、推翻、重构。

在这个对话过程中也是在训练

这是 PM 工作方式上的根本变化。

二、除了 HTML，还有 5 种 AI 画原型工具

上面 3 个 Skill 的产物都是 HTML 代码。

但 PM 实际需求不止这一种。有时候要一张能贴进 PRD 的位图、一份流程图、 Figma 稿。

我把目前真正能落地的另外几种工具盘了一遍。

1 Claude Code / Codex（命令行代理）

最底层、也最强大的一种。

Claude Code 是 Anthropic 出的命令行 Agent，Codex 是 OpenAI 出的对标产品。

有 CLI 版本和桌面端版本。新手可以使用桌面端版本，CLI 版本可以自定义 API。

具体的使用方法可以看我过往文章。

上面我做的那 3 个画原型 Skill 全是跑在 Claude Code 上的。

但即使不装任何 Skill，光是裸用 Claude Code，你也可以跟它说"看这张截图，帮我做一个 HTML 原型"，它会自己理解、自己写文件、自己调试、自己开浏览器预览。

Agent 能直接帮你建好文件、跑通环境、改到能用为止。

这是所有想认真用 AI 做产品的人，迟早要用的工具。

2 图片模型出图

GPT-Image-2、Nano Banana 等。

他们出的图是能贴到 PRD 里的 UI 概念图。

几十秒一张能直接贴进 PRD 的位图原型。中文文字识别几乎不出错。竞品风格图、Banner 草稿、UI 概念图、需求评审用的视觉示意，都是它的主战场。

3 个 Drawio + AI

让 AI 直接出 .drawio 的图纸文件。

使用技能：https://github.com/Agents365-ai/drawio-skill

直接产出 .drawio 文件落到 Obsidian 库里。点开自动调起编辑器，改完保存，Markdown 笔记引用就能调出。

一张架构图随系统演化要改十次。AI 重新生成每次都是新的不带历史，AI 加人工编辑的混合模式，才能让一张图的版本演化轨迹被保留下来。

4 个代理原型 IDE

原型开发环境，如 v0、Bolt.new、Lovable。

v0 最大的特性是生成完直接给一个 vercel.app 的 URL，转发给任何人打开都能用，演示完关掉链接不用清理。

可点击不等于可上线。他们做的都是 demo 级产品，适合用于原型和想法验证。

5 缝合/菲格玛制作

如果你的下游是设计师，最好的路径是直接产出 Figma 格式设计稿。

Stitch 是 Google 出的 AI 设计工具，入口stitch.withgoogle.com，对话框描述页面或 App 流程，直出 Figma 稿。也支持 html 代码导出等多种格式。

Figma Make 是 Figma 官方的 AI 面板，直接在figma.com里调右侧 AI Make 面板，生成的节点天然落在 Figma 工作流里。组件库背靠 Figma 生态最全。

前者适合从零起一个 App 原型，后者适合已经在 Figma 里重度协作的团队接力。两个都能把"AI 出稿 → 设计师精修"这条链路接通。

我把这一年自己用过的、打磨过的所有 PM 相关 Skill 都开源了出来。一共 13 个，按 PM 的工作流分四类：

四、AI 节省下的时间，用来做什么

传统的 PM 发展路线正在快速失效。

当一个会用 Agent 的产品新人，可以在一周内端出来一个能用的小产品，他和一个所谓"高级产品"之间的差距，不再是 title，而是品味。

品味这个东西，没法靠 Agent 速成。

它来自对原型的反复试错、对用户反馈的反复消化、对踩坑的反复复盘。

"基本功"并没有被 AI 所代替，但是积攒基本功的方式变了，

传统路径里，初级产品要花两年练拖控件、对齐间距、写需求文档。

这套基本功今天看大半是浪费。

新方式是借助 Agent大量实践和试错。

你可以一周看 100 个原型、一个月跑 50 个小产品、一年消化 1000 份用户反馈。

前提只有一个：你真的人在场。

每一稿 AI 出的原型都过一遍，改一遍，跟自己的判断对一遍。

AI 把你的练习场放大 100 倍。

这就是 AI 时代的产品基本功，不按传统路径熬资历，而是用 Agent 把试错周期压到极致，再用人的判断把每一次试错的经验沉淀成品味。

初级、中级、高级，这些 title 不再重要。

重要的是你做没做过产品，做过几个，做成了几个。用户是怎么评价的。

PM 这个岗位不会消失。

但 PM 的定义正在被重写，从写需求文档的人，变成用 Agent 自己造产品、并在试错中积累品味的人。

迟早所有人都会切换过来。但红利只属于先动手的那批。
