任何内容都能做成 Skill：从 Lenny 播客到企业知识库

空格的键盘 AISkill知识管理企业应用Lenny 2026-01-22

内容不只是用来对话的材料，内容就是 Skill 。

原创 空格 zephyr 2026年1月22日 11:24

前两天我分享的 Lenny 开源 300 期付费播客文字稿 ，几百万字的播客稿开源了 。

这里面包含了硅谷顶尖产品经理、增长、运营、营销负责人的访谈。

没过多久就有网友 sid 把 Lenny 的 300 期播客——几百万字的逐字稿——转化成了 80 多个可以直接安装的 Skill。

放在了这个网站上： https://refoundai.com/lenny-skills/

我还没看完这 80 多个 Skill，3000 多个对话，就发现了博主完全开源了教程

他是怎么把百万字的播客内容转为 Skill 的： https://sidbharath.com/blog/building-lenny-skills-database/

这个教程彻底打开了我对 Skill 的制作思路，

原来任何内容都可以制作 Skill。

01

Skill 分为 markdown 文件参考文件和脚本文件，对于 md 文件本质就是一大串提示词，以前你使用和创作提示词的场景都可以应用到 skill 的创作，

但更强大的是它的参考文件和脚本文件。

提示词+参考文件（ 风格指南、模板、样例）。AI 能按参考文件的风格，稳定输出高度一致的内容。

提示词+脚本 ， Skill 能做压缩文件、格式转换、联网搜索、数据分析等实实在在的动作。

关于 Skill 的原理可以看我这篇文章：

Claude Skills 完全指南：从入门到精通

我之前归纳的三个方法来创建 Skill：

  • 把提示词转成 Skill
  • 把 SOP 拆解转成 Skill
  • 把聊天对话做成 Skill

但这些内容都来源于个人是有限的。

我们想要做更优秀的 Skill，就可以参考我们 读过的书籍、听过的播客、看过的文章、记过的笔记 。

这是 Sid Bharath 对 lenny 播客转 Skill 的教程给我最大的启发。

甚至对于企业来说，累计了几年几十年的内容都可以转为让 AI 可执行的 Skill。

接下来看下 Sid 是怎么做的/

03

sid 面对300 期，上百万字的播客逐字稿，用了两种方法来尝试：

第一次尝试：自上向下提取（失败）

他让 AI 自动提取播客里所有的"框架"、"金句"、"方法论"。 结果跑了一晚上，得到 3000 多个碎片化的标签，

比如："Netflix 测试发放"、"激活指标优化框架"

看起来很牛，但完全没法用。

因为没人会去搜索一个自己都叫不上名字的标签。

虽然这种方法很符合人的直觉，把内容像切蛋糕一样切下去。

奈何切的太碎了，拿都拿不起来。

第二次尝试：自下向上定义（成功）

他换了个思路：先去定义 "用户到底想干什么"。

比如：

  • "如何排产品优先级"
  • "怎么管理团队，制定北极星指标"
  • "制定增长策略的步骤"

制定了11个分类，11 个分类下又定义了 86 个Skills

对分类和 Skills 的定义也是让 Claude 对文本进行分析而得出的。

然后让 用 Gemini flash 开 1个线程去提取 300 期播客里，跟 86 个技能相关的对话。

总共提取了 3,328 多个对话内容。最后两件事情是:

  • 把内容制作成结构化的数据进行存储。
  • 把内容转成用户可下载的 Agent Skill

可以看下图是他设计的数据模型和 Skill 模板。

按这个数据模型，把内容交给 AI 来处理，最终他做出了 86 个 Skill，每个 Skill 都可以直接被 Claude、Cursor 这些工具加载。

网站可以选择不同领域，查看不同嘉宾的对话、洞察。

即使不用 Skill，看一看内容也值了，毕竟 lenny 的 Newsletter 每年订阅费就近 200 刀了。

04

这个教程让我立刻想到 ：我为什么不把我的内容都做成 Skill？

我读过的书、收藏的文章、Obsidian 里的笔记……

我把上面 sid 的教程发给了 Claude code

我试着做了个 content-to-skill 的技能，

没过一会这个 Skill 就做好了：

接着，我把 保罗·格雷厄姆 的几十篇文章链接发给它。

来试试这个 Skill 的威力。

它帮我提取出了 3 个 Skill。

通过判断 Skill 内容和模型的思考。

可以看到，模型是先对所有内容做了分类拆解，然后使用 Skill-create 的能力创作 Skill。

和Sid Bharath 的思路一致。

效果还是很惊艳的。

下一步，我可以拿它把我之前在微信读书收藏的笔记、书籍做成 Skill。

但还是觉得缺了点什么。

05

没有错， 就是缺了 Script 脚本文件。

生成的 Skill 只有提示词构建的大脑，缺少代码构建的手脚

就在我写这篇文章的时候，我看到 卡兹克大佬 分享的教程 ：

Skills的最正确用法，是将整个Github压缩成你自己的超级技能库。

Sid 的方法是把优质内容提取为 Skill 的"心法"（Insight）。

而 GitHub 上海量的开源代码，就是现成的"招式"（Code）。

只要搜索到优质仓库，都可以转化为 Skill 的 scripts/ 部分。

结合这两点，我现在脑海中有了一个 Skill 制作的终极流程：

当我要制作一个 Skill（比如"增长黑客"）时：

  • Input (内容)： 输入经典的增长黑客文章/书籍。AI 提取核心策略（Prompt + References）。
  • Search (代码)： AI 根据策略关键词，自动去 GitHub 搜索相关工具（A/B 测试脚本、数据分析代码）。
  • Build (构建)： 策略写入 SKILL.md，代码存入 scripts/。

这样生成的 Skill： 既懂增长黑客的理论（来自 PG/Lenny），又有 Python 脚本能帮你跑数据（来自 GitHub）。

感兴趣的话，下一期我来分享上面这个思路的实践成果。

06

我进一步思考，企业内有那么多的文档，该如何利用？

企业比个人更懂得知识管理，尤其对于大型企业，5 年前 10 年前的项目文档都还在。

只要内容的价值还在，这在都能成为有用的 Skill。

你随意打开钉钉、飞书看看，每个部门都沉淀着大量的 SOP 文档和交付物：

  • 产品经理：几十上百份需求文档（PRD）
  • 设计师：设计规范、组件库说明
  • 研发：技术方案文档、代码规范
  • 运营：活动复盘、用户运营手册

这些东西，现在大多躺在企业网盘、钉钉、飞书文档里吃灰。

但如果你把它们发给 AI 制作成 Skill，会发生什么？

  • AI 能深度理解你的业务和系统，因为它读过了你所有的 PRD，知道你的产品架构、用户场景、交互逻辑。
  • AI 能输出风格一致的交付物，因为它读过了你所有的历史文档，知道你的写作风格、格式规范。
  • AI 能打通上下游工具，如果再接入原型设计（Figma）和代码生成的 Script，AI 可以直接从需求文档生成原型，甚至生成代码骨架。

它读过了企业所有的沉淀，企业的风格， 甚至能接手企业员工的工作。

就拿我产品经理岗位来说，把我写过的需求文档、制作原型的工具和代码制作成 Skill。

用户提出需求，就能产出需求文档和原型，人类再审核进行开发。

产品岗位的职责就变了。

因为 Skill，一个人操控多个 Agent 来干活 的场景已经实现了

在企业中也不会太远。

07

不管是企业还是个人，"上下文" (Context) 才是最宝贵的东西。

内容不只是用来对话的材料。内容就是 Skill 技能。

你的收藏夹、知识库、读过的书、做过的项目，都有机会成为驱动 AI 工作的燃料。

但AI 越强大，你越应该去做那些"没用"的事。

因为 AI 能做的是那些"有用"的事：整理文档、写代码、分析数据。

这些事它会越来越擅长。

而真正稀缺的，是 AI 无法替你获取的"上下文"：

  • 和一个聊得来的朋友深夜的一次对话
  • 在一个小众展览里看到的一个灵感
  • 钻研冷门爱好时偶然发现的一本绝版书

这些"没用"的事，才是独属于你的上下文来源。

把这些独家的上下文喂给 AI，它就能帮你干出别人干不出的活儿。

人机协作的终极形态：你去获取独家上下文，AI 帮你把上下文变成技能。
