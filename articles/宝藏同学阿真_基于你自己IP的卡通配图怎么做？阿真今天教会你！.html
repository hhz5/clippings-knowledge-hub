这就是我最近新做的一个 Skill，它可以帮你制作带有你个人 IP 的信息图的 Skill。有了这个 Skill，你就可以基于文档或者文章，生成这种带有你专属 IP 信息的图表了。

不只是好玩，这种信息图会带来更多的优势。比如，如果你是长期做公众号、小红书、视频号或者任何内容账号的博主，你会慢慢发现，这样你的内容会有更稳定的识别度。

普通的信息图只能解决一篇内容怎么去讲清楚，而带有个人 IP 的信息图，可以让别人看到这张图时，能不能想起你以及能不能记住你。

每张图里都有一个稳定的角色，固定的外形、表情、动作习惯以及视觉风格，会让你积累起自己的个人内容资产。

久而久之，读者记得的就不再只是某一篇文章或者科普，他会记得这是某个人的 IP。这才是 IP 信息图的价值：它不会单纯为了可爱而可爱，除了可以让信息更加清晰地展现，同时也会让内容变得系列化、可识别。

Skill调用

我这里增加了一个要求，让它不要调用其他 Skill 或者翻阅往期的文件，因为我不希望其他 Skill 或往期文件影响到我这里的结果，导致我呈现给出的结果和大家在那边看到的不一样。大家在使用的时候，只要说调用这个 Skill 就可以👇

调用了这个 Skill 以后，可以看到它就会开始引导。

图片上传

首先，它会问你，让你发送新的 IP 原图或者角色的描述。如果你已经有 IP 的话，就直接把 IP 图发给它，并告诉它这就是你的 IP 原图；如果你没有这个 IP，可以给它一张参考图，让它帮你生成一个这样的卡通漫画 IP。

这里我给了一张 AI 生成的、但是真人风格的照片。👇

Codex 它会首先读取我在 Skill 里面设置的一个 IP 的 DNA 分析及样本提取，然后给到我们第一轮草案，以及正面全身确认图的提示词。

这里的图片优先使用全身图，并且背景简单一些，效果会更好。如果是半身照的话，它会智能地进行下半身的细节补充。

照片也不是只能使用真实照片。如果你有其他已经做好、或者比较喜欢的卡通形象，同样可以把它提取为“正面全身照”的提示词。

这里我附上几个其他风格的图片，以及它们的输出效果的展示，方便大家了解什么样的图是可以放的（其实基本上没啥限制，是个图都能好好提取的）👇

正面全身图与三视图

接下来通过 Skill 的引导去要求 Codex 先生成正面全身确认图，再生成两头身的卡通 Q 版图片。

但是这里也并不一定要是两头身。

两头身会看起来非常短，也非常可爱。如果你更喜欢比例看起来更修长的，可以基于自己的需要，比如采用七头身、三头身等等。👇

不同的头身比会带来不同的视觉感受。但是总体而言，还是看调性，或者说你实际的需要，如果需要看起来更有高级感，可以选择更高的头身比；如果需要看起来更有亲和力，则可以考虑更短的头身比。👇

表情包

接下来可以选择前面你已经确认的那个表情包作为参考图，让它继续生成独立的单张表情动作包。

这里的表情动作包其实也是为了后续如果做信息图，有其他不同视觉表现的 IP 可以作为一个一致性的参考。

这一块如果没有也没有关系，实际上有了三视图生成图片的话，就已经有了一个锚点。有这个表情动作包的话是锦上添花。当然，如果已经做到这一步，你甚至可以直接再将这些静态的表情动作包做成动态表情包。👇

有的时候在生成表情包时，可能会出现一致性方面的细节问题，比如手势或者是身体比例发生了变化。

Codex 会先进行整体质检，如果发现不符合要求的地方，会主动进行处理。

比如上方这两张表情包，在制作第一张和第二张时，它起初生成了一张三头身的图片，但在后续质检时发现了比例偏高的问题，于是它就自动重新生成了。

当然，也有一些情况是 Codex 通过了质检但没有检查出问题的。这种时候，你可以直接复制这张图片，然后让 Codex 基于你的具体要求去重新生成。

要注意在执行打包交接之前，要把正面照、三视图和表情包都逐一进行细节检查，免得以后出现参考图误导 IP 形象的情况。表情包确认了没有问题之后，你就可以要求它打包交接了。👇

上面可以看见，在上面的“打包交接”回答之后，它提供了一个“下一步建议”。这个建议在 Skill 执行的每一个步骤中，几乎每一轮都会出现，引导你继续完成后续的操作。

我们打包完这个档案包后，目前只完成了“提取 IP 并将其制作成 IP 档案”这个步骤。接下来的任务是让它将这个档案与信息图结合起来，即通过“IP 加信息图”技能，最终合成一个完整的、属于你的“IP 信息图 Skill”。

所以我们会继续要求接入下游漫画信息图技能，合成一个完整的基于这套 IP 的 Skill。到这一步结束，它就已经做好了一个 IP 信息图 Skill 了。它会给到一个名称，这个名称其实就是带有你的 IP 的 Skill 名称了。👇

这时候大家可能会觉得，哦天哪，这个 Skill 的名称也太长了吧。

那么我们也可以继续去修改它的触发词。所谓的触发词，就是下次你说什么的时候这个 Skill 可以出现。

比如说，上面这个 Skill 的名称太长了。我们可以要求它，下一次我想要调用这个 Skill 的时候，我说出某些特定的关键词作为触发词，你就直接调用这个 Skill。

你看我这里说“向日葵女孩信息图”，下次我就可以说这个，直接调用这个 Skill 了👇

太棒了！到这里，你就已经知道了怎么做一个基于自己 IP 的 信息图 Skill 了！

那么接下来，我们就可以直接使用这个已经做好的 Skill，并且基于它呈现的结果，进行进一步的细化和调整了。

Skill调用与修改

现在我开了一个新的对话，然后说：调用这个“向日葵女孩信息图”Skill。

等它调用了，接下来我们就可以直接给到它文档、文档的路径或者是飞书云文档的链接（如果你安装了飞书 Cli 的话）。

在这一步，你也可以要求它一共生成多少张信息图，并在前期与其核对以下细节：

  1. 生成范围：具体哪些方面或哪些段落需要生成信息图
  2. 细节标准：信息图的信息量大小
  3. 视觉要求：包括排版和色调等具体要求👇

在这里我增加了一个步骤，让它首先生成信息图的提示词。这个步骤可要可不要：

  1. 如果你直接使用 Codex，那么可以不用它生成提示词，直接基于信息图的信息去生成图片。
  2. 如果你使用的是其他的生图工具，那么这个信息图提示词就可以用在其他工具上。

但是记得，如果是使用其他的生图工具（比如即梦）的话，还是要给到固定的参考图。可以是之前生成的三视图。

要复制的生图提示词，完整内容如下：👇

如果你直接使用的 Codex，那就直接让它生成图片就可以了。👇

如果希望图片能够换一个比例，也就是一句话的事情。👇

同时，你也可以要求它的版式更多元，或者信息量更丰富，或者信息更少，以达到更多不同的版式和更加丰富的视觉效果的目的。

虽然 Skill 里面已经加强了限制，但经过我测试，少数情况下依然会出现下列这样的问题（你看到文字很多、图片很小，然后它还给了一个 HTML 的文件），那么就代表 Codex 可能直接使用了网页生成的能力。
