7 个案例把飞书用作 Agent 的操作系统

空格的键盘 AI飞书Agent 操作系统CLI效率 2026-06-19

空格丶 空格的键盘 2026年6月18日 17:12

昨天就在飞书群里看到这场直播预告。张咋啦也在嘉宾名单里。我关注挺久了，每次她聊飞书的玩法都让我想动手试试。

除了她之外，名单上还有几个我蹲了很久的 AI 博主：人民公园说 AI 的苏辰、互通有无的卓霖、还有苍何。

我挺好奇不同人对飞书的用法的，特别是有了 CLI 的能力后，飞书有太多可挖掘的场景了。

我把手头的活儿停下，看完了一个多小时直播。

听下来觉得每个嘉宾的用法都颠覆了我对飞书的想象。

先说下我自己是怎么用飞书的

我日常写文章在 Claude Code 里，写完之后用飞书 CLI 一句话把内容推到飞书文档。多端编辑、随时调整，最后从飞书同步到公众号、小红书、视频号。 飞书在我这边是"承载端" ：Agent 写完，结果倒进飞书，剩下的协作和发布我自己来。

另一件事是 onepod。每天定时抓我订阅的播客字幕，自动推送到飞书文档，再同步到我的个人网站。整条链路我也没管过，跑了大半年。

这两件事让我觉得"飞书 + Agent "场景也就这些了。

直到这场 Demo Day。

7 个人，从聊球的卡片到接 Codex 修 bug 的协议，从睡觉时自动写稿的定时任务到剪口播视频的 Skill。看到一半的时候我就反应过来：

飞书不只是承载内容的终端。它是 Agent 的操作系统。

操作系统有四个核心能力：进程调度、文件系统、消息总线、权限管理。

到 Agent 时代：

- 进程调度 = 谁来触发 Agent？人手动喊？定时任务？事件驱动？

- 文件系统 = Agent 产出的东西存在哪？怎么沉淀？怎么被下一个 Agent 读到？

- 消息总线 = Agent 之间怎么传消息？怎么协作？

- 权限管理 = 谁能调谁？数据谁能看？

下面我总结了下这几个嘉宾提到的用法，以及他们开源的 Skill。

1 张睿 Zara：飞书文档里跑 HTML ，Bridge 把 Coding Agent 接进 IM

她演示了飞书文档里直接跑 HTML 。

Agent 输出的是一张可交互的图表、一组带样式的卡片、甚至一个 mini 应用。这些 HTML 组件在飞书里能评论、能共享、能挂权限。

Bridge 是她另一个开源项目，可以把本地的 Claude Code 和 Codex 桥接到飞书 里，让 Claude Code/Codex 成为飞书里的一个 bot，把 coding agent 接回大家每天都在用的协作场景里，让对话、任务、卡片、文档和会话记录都能在同一个环境中流动。

在Terminal输入一行命令就能安装：

npx @larksuite/cli@latest install

Agent 在 IM 里被聊天触发、在文档里渲染产出、在多维表格里被工作流调度。飞书把 Agent 时代最难解决的"渲染怎么办"和"触发怎么办"，用现成的产品组件全接住了。

2 苏辰：飞书卡片 + CLI 调 Codex，让 Agent 直接读"飞书里的私人数据库"

苏辰是《人民公园说 AI》的主播，他做了一个叫"小书童"的足球比赛 Agent，每天看比赛、出战报。比赛卡片直接做成飞书卡片在群里推。

但让我停下来想了想的是他后面那段。他说他还有一个 Agent 叫AI早晚报，每天抓行业资讯，选择一个主题就能制作 5 分钟左右的博客。

最近他在关注 SpaceX 上市，他直接让飞书 CLI 调 Codex 去读早晚报这个 Bot 里最近一个月所有跟 SpaceX 相关的数据，生成一份量化分析报告。

- 资讯沉淀在飞书 Bot 里（ 文件系统 ）

- 提一句话，CLI 唤起 Codex（ 调度 ）

- Codex 读 Bot 数据 → 调用飞书原生表格图表能力 → 输出报告（ 沉淀 + 协作 ）

整条链路里，飞书既是数据库，又是调度器，又是渲染层。

苏辰说了一句话我很认同："在我们不要 GUI 之后，人可以跟 AI 直接交互，或者人可以跟数据直接交互。"飞书 CLI 这种能力就是把"人和数据之间的那层 GUI"砍掉。

3 熊典：AAMP 协议把 Codex 接进多维表格的每一列

熊典是飞书项目产品经理。

他使用飞书官方做的 AAMP 协议的应用场景

Feishu Docs - Image

现场演示是：网站有几个 bug，bug 收集表里两行任务，引用了 codexchat 这个 Agent 邮箱。提交瞬间，本地两个 Codex worktree 自动拉起来，并行修 bug。修完返回 MR 链接到多维表格，再点一个"一键上线"按钮，部署完成。

中间没有任何"打开 Codex、贴提示词、等返回、复制结果"动作。

他做了一个叫 AAMP 的开源协议，给每个 Agent 分配一个邮箱地址，多维表格里只要填一行任务、引用 Agent 邮箱字段，那一行就会自动派给本地的 Codex 去干活。

AAMP 就是 Agent 时代的 IPC（进程间通信）。每个 Agent 有地址、有信箱、有调度器，多维表格是任务队列，工作流是定时器，仪表盘是控制面板。

而且不止 Codex。 Claude Code、OpenClaw 等任何符合协议的 Agent 都能接进来。多维表格的每一列、飞书项目工作流的每一个节点、甚至 GitHub Issue 的评论区，未来都可以直接调用本地 Agent。

熊典说："让 agent 的工作自然地发生，而不是我需要在 Codex 里面跟它讲话。"

4 卓霖 ：飞书 CLI 调 HyperFrames Skill，远程出口播视频

卓霖是互通有无 AI 俱乐部的发起人，她演示了一条"拍完素材直接发飞书，剪辑全部给 AI"的视频生产线。

具体路径：手机拍口播素材 → 发到飞书 → 飞书 CLI 调用 HyperFrames 的开源 Skill → Cloud 调用 Remotion 生成成片。她现场放了一段完全用这条链路跑出来的视频，效果完全可发布。

HyperFrames 安装

npx skills add heygen-com/hyperframes

让我觉得有意思的是： 她不用打开剪辑软件，不用碰电脑，整个生产流在飞书对话里完成。

这是飞书作为操作系统的另一个能力： 端能力的延伸 。手机、桌面、CLI、卡片，对 Agent 来说都是一个统一的 IO 接口。卓霖的口播素材从手机进入，成片在 CLI 里输出，整个过程飞书把"端"这件事变成了透明的。

她引用了张达的一句话："很多人在表达需求的时候会被想象力给限制住。" 这句话放在 Agent 操作系统这个语境里特别对——当工具不再切换的时候，想象力才有地方落脚。

5 李青：邮箱订单自动审核，多维表格一键归档

李青是来也科技的 AI 产品经理，她演示了一个 B 端最高频的痛点：业务人员每天处理大量邮箱来的订单附件，逐字读、人工录入、人工核对。

她做了一个 Skill，安装后只要说一句"帮我处理过去 24 小时内的所有订单附件"，Agent 就自动拉邮件、读 PDF 附件、识别商品、对照内部 SKU 库、检测价格偏差、把异常订单单独标红、所有信息归档到多维表格。

业务人员的工作从"逐字录单"变成"只看异常"。

让我注意到的细节是：这个 Skill 还可以让用户用自然语言描述自己企业的业务规则，AI 自动生成多维表格里的计算公式。 配置工作流这件事本身，也被 Agent 接管了。

Skill 安装：

帮我安装这个skill：npx skills add laiye-ai/adp-cli -y -g

6 苍何：GEO 诊断 Skill 直接输出飞书文档

苍何是 GitHub 万星项目开发者，他这场演示了一个给品牌做 GEO（生成式引擎优化）诊断的 Skill。

给一个品牌名，Skill 全网搜索 + 多模型对比 + 评分输出，最后落成一份精美的HTML/飞书文档

让我特别有共鸣的是他说的那句：这些都依赖飞书 CLI 的能力。

一个垂直领域的专业 Skill，最后的呈现层完全交给飞书原生组件，不用自己做前端。

飞书把"文档和 HTML 报告呈现"这件事抽象成了系统级能力。

7 泛函：飞书 CLI + Codex 定时任务，他睡觉时 Agent 在写稿

泛函是 02 年的猎头，但他这场演示让我意识到： Agent 操作系统的核心是"Agent 在你不在的时候还能干活"。

他的工作流：每天晚上 12 点，他睡觉了，Codex 通过飞书 CLI 自动跑一个定时任务。

这个任务会读他白天所有飞书会议的妙记、读他得到大脑里录音卡录的语音，按他训练好的"个人内容风格 Skill"提炼选题、生成初稿、给客户敏感信息脱敏。

第二天早上他打开飞书，文档里有他昨天的全部洞察 + 5 篇成稿。

他说："以前要让 AI 的内容符合你的审美要求，这个事情还挺复杂的，但是有了飞书 CLI 之后变得非常简单。"

原因很简单：飞书 CLI 让 Agent 能直接读妙记、读历史文档、读他改稿前后的版本对比，自动反推他的审美偏好。

当 Agent 能在你睡觉时干活，飞书就不只是个协作平台，是 24 小时运转的数字工厂。

写在最后

上面 7 个案例数据沉淀在飞书、调度在飞书、产出在飞书、协作在飞书。

钉钉、企业微信、Notion、Slack 都接了 AI。但绝大多数停留在"侧边栏加一个 AI 助手"的形态。AI 是访客，工作流是主场。

飞书是少数把 AI 当一等公民接进底层调度的。CLI 让 Agent 能像用户一样操作飞书，AAMP 让 Agent 之间能直接通信，多维表格 + 工作流让 Agent 可以被事件触发，妙记和文档让 Agent 有充足的上下文。

这让可以让飞书 Agent 操作系统成为可能。。

直播结束的时候，主持人王大仙说了一句话："以后我们都不用怕被 AI 替代了，我们要学会雇佣 AI。"

这支团队的总部，可以说就是飞书。

设想一下，周一早上打开飞书，多维表格里堆着 5 个 bug、3 篇选题、1 段视频素材、12 封新订单。没人手动派活，AAMP 协议自动把任务投递给本地 Agent。bug 在 Codex 的 worktree 里被修，选题在 Claude 的脑子里被拆，视频在 HyperFrames 的渲染管线里成片，订单在多维表格里被归档。

我打开看一眼，挑两条审一下，剩下的全部进生产。

这就是 Agent 操作系统。
