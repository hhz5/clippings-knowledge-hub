好故事，不该只停在一句灵感

“一个失聪的调音师，在修复旧磁带时，听见了失踪妹妹留下的求救信号。”

这是一个不错的开头，但离剧本还很远。

谁在阻止他？

妹妹为什么失踪？

他为什么一定要找到真相？

真相揭开后，他又要付出什么代价？

这是适合两小时讲完的电影，还是适合持续铺陈的连续剧？又或者，是一集一个钩子的微短剧？

原点编剧系统希望做的，是陪创作者把这些问题一层一层落下来。

😼

它是一套面向电影、连续剧、微短剧创作的准专业 AI 编剧工作台。不是一个只会“续写”的聊天框，而是一套围绕真实创作流程设计的系统：帮助创作者从一个想法出发，逐步建立完整、可修改、可推进的剧本。

三种创作形态，三套不同的叙事要求

电影、连续剧、微短剧，都叫“剧本”，但它们绝不是同一套写法。

电影：有限篇幅里的完整闭环

电影需要在相对有限的时长中，完成主题表达、人物变化与故事闭环。

它要求创作者更克制：每一场戏都要有作用，每一次转折都要足够有力，人物的选择必须撑得起最终的情感落点。

原点编剧系统会帮助创作者聚焦故事的核心问题、主角弧光、关键转折和终局代价，让故事不只是“发生了很多事”，而是真正完成一次人物与主题的抵达。

连续剧：让人物关系持续生长

连续剧的魅力，在于人物关系有足够的时间发酵。

角色之间的信任、背叛、误解、联盟和反目，不会在一集里结束；主线需要持续推进，支线也要为人物和主题服务。观众留下来，往往不是只为了一个谜底，而是因为他们想知道这些人物最终会变成什么样。

原点编剧系统通过角色、关系、结构和分集规划，帮助创作者把长线叙事放在一个更清晰的全局中管理。

微短剧：高密度推进，每集都要抓住人

微短剧有自己的叙事语法。

开场要快，冲突要强，信息要密，每一集都需要让观众有“再看一集”的理由。悬念、反转、身份揭示、情感拉扯和阶段性爽点，都要被更紧凑地组织起来。

原点编剧系统会帮助创作者更快地拆解单集目标、冲突升级与结尾钩子，让故事节奏不拖沓、人物关系也不失真。

从一句想法，到可写的剧本

原点编剧系统的核心，不是“生成一段文字”，而是协助完成一整条创作链路。

1. 找到故事真正的核心

当故事核心足够清楚，后面的角色、情节和场景，才不会变成各说各话的碎片。

2. 让角色不只是“人设标签”

角色不是单独放在资料库里，而是会进入人物关系、情节推进和具体场景中。创作者可以持续调整人物动机，让人物在故事里真正行动起来。

3. 让结构服务于故事，而不是限制故事

系统可以协助整理故事结构、关键节点和情节卡。创作者可以看到故事的整体走向，也可以随时回到某一张卡片、某一段关系或某一个场景重新调整。

4. 从“故事大纲”走到“具体一场戏”

真正困难的部分，往往从这里开始。原点编剧系统帮助创作者把抽象的故事推进到分集、场景和剧本正文。不是只停留在“故事梗概”，而是逐步走向真正可以写、可以改、可以继续打磨的剧本。

AI 是协作者，不是替代者

我相信，剧本创作里最不能被替代的，始终是创作者的判断。

AI 可以帮助生成方向、补足结构、发散可能性、整理素材；但人物的灵魂、故事的选择、情感的分寸，仍然属于作者。

所以原点编剧系统更像一张“第二工作台”。

当你卡在角色关系时，它可以帮你梳理矛盾。

当你不知道故事如何升级时，它可以提供结构上的可能性。

当你需要快速把一个想法扩写成可讨论的初稿时，它可以帮你迈出第一步。

而当你有了更好的判断时，所有内容都可以被修改、替换和重构。

不是让 AI 把故事写完。

而是让创作者更快进入真正的创作状态。

为认真讲故事的人而做

原点编剧系统适合：

  • 正在开发电影项目的编剧、导演与制片人
  • 需要管理长线人物和多集结构的剧集创作者
  • 需要高密度冲突与强钩子的微短剧团队
  • 正在学习剧作、希望建立完整创作流程的新作者
  • 有故事想法，但总是难以落到剧本的人

它仍在持续打磨，但我的目标很清楚：

  • 让灵感不再停留在备忘录里。
  • 让人物、关系、结构和场景真正连起来。
  • 让每一个认真想讲故事的人，都能更接近自己的剧本。

想自己部署或参与共建？

原点编剧系统目前还没有独立的网站服务或客户端，它以本地运行方式为主：你的项目、剧本和创作数据都保存在自己的电脑中，更适合个人创作、工作室开发与私有素材管理。

基础设置并不复杂，但确实需要你要做点事，建议在AI的帮助下，你大概率会轻松搞定：

  • 安装 Node.js 运行环境
  • 从 GitHub 获取项目源码
  • 在项目目录启动服务
  • 用浏览器打开本地地址即可使用
  • 如需真实 AI 生成，再在系统设置中连接自己的模型服务

完整的安装说明、模型配置方式、常见问题、数据存储说明和更新内容，都已整理在 GitHub 项目主页。即使没有开发经验，也可以按 README 的步骤完成基础部署。

开源地址： github.com/mmlong818/plotcat

需要提醒的是：AI 生成能力需要使用者自行配置模型服务。系统支持智谱 GLM（我日常在用）、Claude、OpenAI、Gemini，以及其他兼容 OpenAI 接口的模型服务；具体配置方法请以 GitHub 文档为准。
