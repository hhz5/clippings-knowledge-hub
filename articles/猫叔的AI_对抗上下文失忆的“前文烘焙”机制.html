对抗上下文失忆的“前文烘焙”机制

原创 猫叔的AI 2025年12月10日 03:11

目的是为了跨会话的内容转移 ，本质上是把 AI 当作一个“压缩算法”，将几千字的对话历史压缩成一个几百字的“存档点”。

在以下场景中，引入“前文烘焙”是必要的选择：

  • 超长视界的任务： 当任务跨度极长（如编写整本书或进行深度研究），直接拼接所有历史会迅速超出上下文窗口。此时必须通过“定期压缩”生成状态快照。
  • 多智能体协作： 不同专长的智能体之间不需要知道对方的所有聊天细节，只需要知道“任务结果”和“下一步指令”。通过交换结构化的消息而非原始对话，可以保持协作的清晰度。
  • 非线性逻辑推理： 如果你的系统需要跨越时间线去检索逻辑依赖（例如：第1章的伏笔要在第10章回收），简单的对话流存储是无效的。需要将语境“烘焙”成依赖图谱（Dependency Graph）或任务树。

失效或低效场景

在以下场景中，强制使用“烘焙”可能会适得其反：

  • 高精度的创意微调： 如果你的指令涉及极其微妙的语气、文风或审美调整（如你提到的“3D立体书风格”），纯文本摘要容易丢失这些“非结构化”的细节。
  • 高度依赖原始顺序的任务： 如果使用了“QA问答对”形式的压缩，会破坏原始信息的流动性，导致系统难以理解上下文的连贯性。
  • Schema 设计不当时： 如果你强制要求“烘焙师”将信息填入一个设计得很烂的固定模板，会导致信息僵化，限制模型的推理灵活性。
  • 简单短任务： 对于短期交互，直接利用 KV Caching 比复杂的语境管理更高效。过度工程化会增加延迟和系统不稳定性。

这里定义了一套 标准的交互协议， 其包含三个模块： 触发指令 、 存档格式 、 唤醒指令 。

模块一：触发指令（Baking Trigger）

使用场景： 在当前对话结束或需要存档时，发送这段话。

原理： 强制模型执行“语境抽象”（Context Abstraction），将非结构化的对话流转化为结构化的 Schema。

# 指令：执行语境烘焙 (Context Baking)
## 任务目标
请作为“语境烘焙师”，立刻停止当前的常规对话，对我们之前的全部交互进行“状态快照”提取。你的目标是生成一个可被另一个 AI 实例读取的【标准工程状态块】。

## 提取要求 (Schema)
请忽略所有的寒暄、废话和中间试错过程，仅保留“结论”和“当前状态”。请严格按照以下 JSON 格式输出（必须放在代码框中以方便复制）：

1. Project_Meta: 项目核心定义（一句话描述我们在做什么）。
2. Critical_Constraints: 已经确定的硬性约束（如：文风要求、禁止事项、格式规范）。
3. Knowledge_Base: 也就是我们在这个会话中已经达成的共识、设定或提取出的关键事实（Entity Map）。
4. Current_Status: 当前进度（已完成什么，卡在哪里）。
5. Next_Action_Queue: 接下来需要立刻执行的 1-3 个具体任务。

## 输出格式示例
\`\`\`
json
{
  "Project_Meta": "...",
  "Constraints": ["...", "..."],
  "Knowledge": { ... },
  "Status": "...",
  "Next_Steps": ["..."]
}
\`\`\`
请直接输出 JSON 代码块，不要进行任何额外的解释。

模块三：唤醒指令（Resurrection Prompt）

使用场景： 打开一个新的聊天窗口（新会话），把上面复制的 JSON 和这段话一起发给 AI。

原理： 类似于“上下文注入”（Context Injection），利用 Schema 快速重建认知模型。

# 角色设定：项目接力者## 背景
我们正在进行一个跨会话的长程项目。我将为你提供上一个会话生成的【工程状态块】。请你读取这个状态块，直接“继承”之前的记忆和设定。

## 你的任务1. **读取状态**：分析我提供的 JSON 数据，内化所有的约束条件和背景知识。
2. **恢复身份**：基于 \`Project_Meta\` 和 \`Current_Status\`，理解你当前的角色和任务进度。
3. **立刻执行**：直接开始执行 \`Next_Action_Queue\` 中的第一项任务。

## 工程状态块 (在此处粘贴之前复制的 JSON 代码)
[粘贴]

---
请确认已读取状态，并直接输出 \`Next_Steps\` 的执行结果，无需寒暄。

为什么要这样做？

  1. 1.压缩比极高：
  2. 1.将几千字的聊天记录压缩成几百字的 JSON，新会话中的 AI 不需要再从头阅读冗长的历史（那样既费钱又容易遗忘），而是直接读取“经过提炼的真理”。
  3. 2.避免“上下文污染”：
  4. 1.在长对话中，早期的错误尝试会留在历史记录里，干扰 AI 的判断。通过这种“手动烘焙”，你可以把那些错误的尝试丢弃，只把“正确的”带到新会话中。
  5. 3.标准化接口：
  6. 1.使用 JSON 或 Markdown 列表是为了让不同的模型（从 GPT 迁移到 Claude ）能通用。
