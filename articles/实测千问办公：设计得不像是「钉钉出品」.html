实测千问办公：设计得不像是「钉钉出品」

一泽Eze AI千问办公钉钉办公软件产品评测 2026-08-03

如何降低门槛，培养用户对 Agent 的信赖？

一泽Eze 一泽Eze 2026年8月3日 12:39

前两天阿里有了新 AI Agent 大产品：千问办公。

有客户端与网页版两个版本，差别不小，前者包含了更完整的能力。

独立客户端

而大家以为该是完整客户端的钉钉版，实则是网页版。

网页版与钉钉当前接入的网页版

原以为千问办公的定位 only for 钉钉（毕竟是宇森接手钉钉后的产品发布）。

实际体验下来，它的生态边界比我想象中开放得多，也有不少很棒的 Agent 产品实现：

  1. 1.IM 互联：从钉钉、微信，到飞书、企微，应接尽可接
  2. 2.专家套件：按岗位职能打包技能套件，而非“请个专家团”
  3. 3.专业工作台：专为设计、PPT 场景打造的人机协作工作台
  4. 4.更多细节：技能自进化、图片&音频生成提升……

本文将从产品设计、能力范围的角度，向你分享千问办公全貌，应该是最全的产品一览了。

　ㅤ

👉 速览千问办公

本次千问办公分为 2 个端：客户端、网页版。

核心的区别在于，客户端拥有完整电脑权限，除了选择工作目录自动读取本地文件外，还有更多 Agent 本地连接能力（包括 MCP、CLI 等连接模式）。

　ㅤ

而网页版运行于云端，少了本地权限能力，只多了「个人网盘」功能区，用于保存用户上传与 Agent 创建的工作文件：

本文主要测试功能更多的独立客户端。先从出乎我们意料的点讲起：千问办公没有把能力边界限定在钉钉里。

　ㅤ

　ㅤ

📲 IM 互联：Agent 时代，搞这么开放？

千问办公最让人意外的地方，是它与钉钉关系如此紧密，但 Agent 连接却没有局限在钉钉、甚至不止阿里生态。

　ㅤ

先是聊天接入的开放性：

在客户端，从钉钉到飞书、从微信、企微到 Slack、WhatsAPP，应接尽可接。

堪称见过的大厂 Agent 里，官方支持接入聊天频道最多的 Agent 产品。（毕竟连友商的 IM 也支持了）

基本都只需要「点击按钮-扫码确认」，就能完成接入。

通过微信 Clawbot 实现的微信互联

　ㅤ

另外，得益于今年 MCP、CLI 等连接器生态的普及，千问办公第一时间预置了一些可接入的应用。

还是得讲一下钉钉生态的打通，允许 Agent 读写钉钉上的日历、联系人、群聊、任务和审批等：

1）既可以自动整理与某个好友、群的任意时段的钉钉消息。尤其是可以把某个人在单聊与共同群聊里的所有消息都找出来

2）也能替你自动向人、群发送消息

打开思路，还能给千问办公设置定时任务，做到类似「每天自动整理信源，向群聊发送日报」等组合技。

　ㅤ

在外部生态这块，连接器板块也在陆续增加各种选项，拓宽 Agent 可触达、管理的领域。

包括用户自己电脑内的 Mac 系统日历、提醒，Microsoft 365 套件；以及外部的 飞书文档、Notion、Supabase、高德云图，均已支持接入。

当然，也可以自定义 MCP 连接，为特定需求用户留了口子。

　ㅤ

　ㅤ

📦 专家套件：被正确定义的「Skill + 连接器」组合包

我比较喜欢千问办公对「专家」模式的定义，和朋友讨论后都以为妙绝。

1）为什么说是正确的定义？

Agent 发展到 2026 年中，我依然不支持在任务中「请个专家」，或者「拉个专家团组合执行」的说法。（个人真实感想，比较早之前也在即刻提过。）

  • ㅤ 先是混淆概念：大部分「专家」只是同一个 LLM，披着不同 Context 外皮，在玩角色扮演，算不上真「专家」。加之“我从专家市场雇个专家”，不得先通过我的面试？这种「雇佣」关系自带不信任感。
  • ㅤ 再者，每个 Agent 任务都请「专家」站台，总有乱糟糟的感觉。好像不是我来把控任务，而是任由请来的「Agent 专家」们摆布。

　ㅤ

千问办公把说法的重心放在了「套件」，淡去「专家」人设。

　ㅤ

如果说：

  • ㅤ 「技能」是做某个特定任务的 SOP，装上目前已上架的「工作周报、数据分析、长文写作」等技能，就能让 Agent 按对应流程，产出符合预期标准的成果。
  • ㅤ 至于「连接器」，甭管背后是 MCP、CLI 还是 API，用户只需要知道：它能把浏览器、系统日历、钉钉、飞书，乃至 Supabase、Vercel 项目，以及企查查、北大法宝等外部数据连接起来，供 Agent 调度。

　ㅤ

那么，「专家套件」则是组合 Skill、连接器的职责能力包：

Skill 告诉 Agent 具体怎么做，连接器把真实数据和工作环境接进来，加之把 Skill 预置为快捷指令，实现打包场景的低门槛一键使用。

比如投研分析、合同管理、企业法务等，每个套件还标注了出品团队。

　ㅤ

这是一个很棒的视角转变：以用户的职能认知视角，引入技能、连接器，形成完整的场景能力包，既方便理解，也比一个个装零散技能、连接器方便不少。

比如我平时很少装单独的 Skill。临时想审查一下合同，我也不愿意专门找一个 Skill，用完还想着删。

但如果你告诉我，我的办公 Agent 可以一键安装「合同管理」套件，从而具备一套相对完整的合同管理能力？——那我觉得太好了，谁不希望自己的 Agent 能力再宽一点呢？

套件还支持整体开关，不用时可以临时关闭，也更方便统一管理。

　ㅤ

　ㅤ

2）从一键 fork 定制现有套件，到组织复用

安装只是第一步：

  • ㅤ 用户不仅可以自行创建套件：告诉 AI 想要新建一个专属套件，AI 就会问他职业方向是什么，平常有哪些需求、要连接哪些数据，就能 0~1 自建完整工作套件
  • ㅤ 还能一键 fork 定制市场上的套件 ⬇️

　ㅤ

比如我希望在市场已有「合同管理」套件上，增加「合同风险速查」能力：按我的审查标准校对我给的合同，并用 HTML 可视化风险清单列出问题。

⬇️

可很方便的按以下流程，对套件进行一键 fork 与改造：

  1. 1.选择定制套件
  2. 2.输入改造要求

　ㅤ

过程中，AI 会继续询问我“有没有报告模板”“主要关注哪些类型的风险”。

确认信息后，就能一键完成改造。改好后，套件中的新技能同样可以通过快捷命令调用。

一键按照套件内的配置，得到预期结果。⬇️

从长远来看，不仅每个人都能从市场里的现成套件开始，改造出更贴合自己工作习惯的 Agent 方案；组织内的 AI 先行者，也能方便地为部门定制可复用的“岗位”套件，从部门规范文档沉淀转向 Agent 套件沉淀，提升组织 AI 效率。

　ㅤ

　ㅤ

💻 专业工作台：网页、PPT 设计，并一键发布为在线网页

除了通用模式外，千问办公里预置了设计、幻灯片、写作三个特定场景模式。

1）设计模式：一键制作 AI 思维导图产品

千问办公在设计模式中，提供了特殊选项，包括参考 Airbnb、Apple 等数十种风格；选择设计线框图 or 高保真原型；指定 shadcn、Ant Design 等组件库。

也支持自行创建前端设计规范，方便稳定复用已有设计习惯 ⬇️

要求：做一个 Figma 风格，Chat 为主要交互，可按各个节点框选与对话的 AI MindMap 的高保真原型

Agent 自动切换到设计工作台模式：人可通过画布功能，对生成页面进行所见即所得的编辑（但在我实测时，发现目前编辑能力开放有限，很多调节受到限制，得等他们继续开发）

4）一键发布网页为在线链接

3）Agent 技能、规则自进化

在「设置-意识」中可以看到，客户端藏了 AutoDream 能力，能自动归纳会话记忆，进化技能。

基于记忆的自进化还是对普通用户来说，Agent 越用越顺手的一环。我在有限的实测过程中，感觉并未触发？

但在首发阶段就上线了该能力，看来在产品规划里，降低 Agent 使用门槛是相当重要的指标，期待团队的后续优化。

　ㅤ

　ㅤ

🎐 写在最后

说千问办公「不像钉钉出品」，是因为它没有像大部分人预想的那样，把 Agent 的使用边界限定在钉钉里。

从现有形态来看，它不仅想让 Agent 服务好钉钉用户，也想承接使用其他办公产品的用户群体。

　ㅤ

千问办公刚刚发布，还有不少 Agent 稳定性、双端一致性问题待打磨。但并不影响它在思考「如何让 Agent 适应人的工作习惯，让更多普通人和组织更容易上手」，并将阶段结果呈现在产品细节里。

　ㅤ

国内各类 Co-work 产品的竞争逐渐进入白热化阶段，接下来，如何让用户打开产品第一眼就知道自己该从哪开始，以及培养对 Agent 成果的信赖度，会变得更加重要。
