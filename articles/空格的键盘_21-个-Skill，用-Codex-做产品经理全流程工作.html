留给垂类 Agent 的机会不多了。

这是我最近使用 Codex 最大的感受。

一个应用，已经同时满足了我的 内容创作、软件开发和产品经理工作 。

它的内置浏览器，已经让我不太需要单独打开 Chrome 了。

有了 Codex，写作 Agent、设计 Agent、产品经理 Agent都可以定制化。

一个通用 Agent，加上一组 Plugin 和 Skill，就能自己组装出特定职业的工作台。

这次，给大家演示下我在 codex 是如何实现需求调研、竞品分析、原型、PRD、评审、埋点和数据分析的。

从打开网页到发布站点，全程没离开 Codex，下面案例也可以代入到 Workbuddy、Qoder 这类通用 Agent 中。

01

先装上产品经理的 Skill

这次使用的是我做的 PM-Skill 2.0。

地址：github.com/SpaceZephyr/pm-skills

目前一共 21 个 Skill。

复制上面地址，告诉你的 Agent，让它帮你安装，安装完成后，你可以指定 Skill，也可以直接告诉 pm-master ：

帮我把这个需求从调研、原型、PRD、评审、埋点一直推进到上线。space

下面我用腾讯云的一个界面做案例，简单演示一下。

第一步：调研和竞品

根据下面界面设计来进行调研，再出原型。

界面可以直接在 codex 里打开，方便 AI 阅读。

用 pm-survey-designer 生成问卷。

第二步：把网站变成原型

原型有两种做法：图片转原型，或者网站转原型。

只要网页能打开，我更推荐网站转原型。

Codex 有内置浏览器，不需要像以前那样先把网页 download 成 HTML，再丢给模型识别，也不用在终端和 Chrome 之间反复横跳。

我直接在 Codex 里打开腾讯混元控制台，然后说：

代码块Plain Text 自动换行复制使用 pm-url2proto 复刻当前页面。

它自己识别页面、创建 Next.js 项目、启动本地服务，再把结果打开在旁边。

下面是复刻后的界面，和原图差别不大，也可以再对话，做的更精细一些。

如果手里只有截图，就用 pm-image2proto ；

要是还要交给设计师编辑，就用 pm-image2pencil ，可以转成可编辑的设计稿。

第三步：PRD、评审、埋点和问卷

原型完成后，继续调用 pm-prd-writer 。

PRD 会直接写进原型，不需要再单独打开文档。

页面里可以切换查看产品目标、用户角色、功能清单、异常流程和非功能需求。

然后用 pm-review-board 让产品、设计、前端、后端、测试和业务六个角色先喷一遍。

这次它直接给了「暂不进入正式开发」，并找出 3 个阻断项和 7 个问题

最后调用 pm-tracking-spec-writer ，生成 15 个埋点事件、字段字典、QA 清单和验收 SQL；再把前面的 10 道问卷一起放进去。

最后，它输出了一份完善的埋点方案。

AI 让问题和分歧提前出现。

第四步：把所有产出变成一个站点

最后，我让 Codex 调用了 Sites 插件，把原型制作成同事可访问的网站。

它在页面底部加了一个默认收起的悬浮入口，可以切换原型、PRD、评审、埋点和问卷。

然后自己完成构建、测试、保存版本和发布。

最终效果：hunyuan-product-hub.wzfh520.chatgpt.site

我最后拿到的是一个可以直接发给团队的链接， 给 到别人能打开、能看懂、能继续讨论。

02

上线以后，还能继续

上线后数据跌了，就把数据表交给 pm-analytics ；

想验证新方案，就接 pm-experiment-designer ；

项目结束后，再让 pm-postmortem-writer 做复盘。

整条链路可以一直往下跑：

代码块Plain Text 自动换行复制调研 → 竞品 → 原型 → PRD → 评审 → 埋点 → 实验 → 分析 → 复盘

上一环的输出，直接成为下一环的输入。

产品工作成了一条可以持续运行的工作流。

03

最后

以上就是我在 Codex 内跑通的一套产品经理工作流程。

你不一定要用 Codex。

如果你在用 WorkBuddy、Qoder 或其他支持 Skill 的 Agent，也可以照着这条流程搭一遍。

如果你是其他职业，也可以试着把自己的工作拆成几个环节，给每个环节配一个 Skill，再让它们共享同一份上下文。

当办公流程真的在一个工具里打通之后，你会发现：很多垂类 Agent，原来只是通用 Agent 里的一个工作流。

留给「模型套壳型垂类 Agent」的机会不多了，留给工作流、数据和界面的机会才刚开始。
