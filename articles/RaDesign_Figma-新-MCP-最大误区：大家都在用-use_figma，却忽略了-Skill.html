“啊， Figma MCP 不是早就有了吗？”

“哦，现在 Codex 会在 Figma 里画东西了。这有啥？” 

上次写到的 Codex 和 Figma 双向互通，Figma 着急了！Codex 和 Figma 双向构建前端 UI你可以用 Codex 写完整网站、生成 UI、但是感觉还是差点意思，还是得中间来回跳！

本质问题就一个：AI 进不去 Figma。

但这次，Figma 把这个问题直接解决了。

 一 

这次 Figma MCP，到底和之前有什么本质区别？

之前的 MCP，是让 Codex“看见 Figma”。
现在的 MCP，是让 Codex“进入 Figma”。

Figma 在 2 月 26 日官方文章里，重点讲的是 Codex 和 Figma 之间的双向流动。一边是从 Figma 把设计上下文交给 Codex，让它更好地生成代码；另一边是把已经跑起来的真实前端界面，通过 generate_figma_design 再带回 Figma，变成可编辑的 Figma 图层。Figma 自己对这件事的表述很明确：“bring real, running interfaces into Figma”，也就是把真实运行中的界面拉回画布里继续讨论和迭代。

换句话说，上一篇文章里的核心，不是“AI 在 Figma 里做设计”，而是：

设计和代码终于能来回流动了。

图片来自：Figma

这个阶段的 MCP，最关键的两个能力其实是：

第一，从 Figma 读上下文给 Codex。
比如通过 get_design_context，把布局、样式、组件信息传给 Codex，帮助它做更有设计依据的代码生成。文章里明确写到，用户可以复制某个 frame 或 node 的 selection URL，然后让 Codex 基于这段设计上下文去实现界面。

第二，把代码生成的真实界面带回 Figma。
也就是 generate_figma_design 这条链路：当你的应用已经能运行了，Codex 可以把网页或本地运行界面的 HTML / UI capture 转成可编辑的 Figma frame，用来做对照、讨论、评审和继续迭代。

所以，如果只用一句话概括上一次的 MCP：

上一次的 MCP，重点是“连接 code 和 canvas”。

它让设计稿不再只是静态参考，也让代码不再完全脱离设计环境。但在这个阶段，Codex 更多还是一个在 Figma 外面工作、再把结果带回来的角色。

二

那这次新的 MCP，又新在哪？

这次不一样了。

Codex 可以找到并利用所有重要的设计上下文。 

https://www.figma.com/blog/the-figma-canvas-is-now-open-to-agents/

图片来自：Figma

3 月 24 日官方文章里最关键的一句话其实是：agents can now write directly to your Figma files。也就是说，agent 现在不是只读取 Figma、引用 Figma、转换 Figma，而是可以直接写入你的 Figma 文件。

通过 use_figma，Codex、Claude Code 这类 MCP client 可以直接生成和修改设计资产，而且这些资产是能和你现有 design system 关联起来的。

这就意味着，Figma 这次开放的不是“更多上下文”，而是：

把画布本身开放给 agent 了。

以前 Codex 更像是在设计稿外围工作：

  • 读设计信息
  • 生成代码
  • 把运行结果搬回 Figma

现在 Codex 可以直接在画布里做这些事：

  • 创建和更新 Figma 文件
  • 修改 component
  • 调用现有组件和变量
  • 按 design system 生成新设计资产
  • 在已有画面上继续改，而不是只做一次性的导入或还原

所以这次真正的变化，不是 “Figma 支持得更好了”，而是：

Codex 的角色，从“代码生成器”变成了“画布里的协作者”。

三

这次更新最值得设计师注意的，不是 use_figma，而是 skills

如果你只看到 use_figma，很容易理解成：

“哦，现在 Codex 会在 Figma 里画东西了。”

但 Figma 这次其实反复强调的另一个关键词，是 skills。

官方文章里说得很清楚：
开放画布给 agent，只是给了它访问 design system 和文件的能力；而 skills 定义的是 agent 如何使用这些访问权限，包括流程步骤、顺序、约定，以及什么才算符合品牌和规范的结果。Figma 甚至还专门提到，skills 可以把团队原本写在文档里的规范，变成 agent 实际执行时会遵循的规则。

视频详情

这点对设计师特别重要。

因为过去很多人对 AI 设计的失望，根本不是因为 AI 不会画，而是因为它：

  • 不懂你的组件体系
  • 不懂你的 spacing 规则
  • 不懂哪些变量该复用
  • 不懂品牌感和页面层级
  • 不懂你们团队默认的设计判断

而 skills 的意义就在这里：

MCP 让 Codex 能进去，skills 才让 Codex 知道进去之后该怎么干。

这也是为什么 Figma 这次不只是发了一个工具，还给了好几类示例 skill，比如生成 component library、用现有 components 和 variables 生成设计、把 design token 和 Figma variables 同步、把现有设计连接到 system component 上等等。

 四 

对设计师来说，这意味着什么？

如果用一句很现实的话来说：

以前你是在用 Codex 帮你“实现设计”。
现在你可以开始用 Codex 跟你一起“做设计”。

这两个工作流完全不是一个量级。

以前你最常见的方式，大概是这样的：

  • 在 Figma 里出稿
  • 把链接或截图发给 Codex
  • 让它写代码
  • 跑起来后再比对
  • 如果不一致，再回到 Figma 或代码里继续改

而现在更像是：

  • 你给 Codex 目标
  • 它直接进入 Figma 画布
  • 用你已有的组件、变量和结构生成页面
  • 你在画布里继续判断、微调、推进
  • 再把最终结果带回代码环境

你会发现，这时候 Figma 不再只是“交付设计稿的地方”，而开始变成：

AI 和设计师共同工作的现场。

这件事，对设计师、产品设计师，甚至对正在自己做产品的设计师来说，影响都会非常大。

真正的变化不是“AI 更强了”，而是设计工作流开始重组了

我觉得这次最值得警惕，也最值得兴奋的一点是：

以后你跟 Codex 协作，可能不再是“写一句 prompt 看结果”，而是要开始管理三层东西：

  • 你的目标和需求
  • 你的 Figma 设计系统
  • 你的 skills / 规则 / 工作流说明

因为未来真正高质量的结果，不会来自一句很会写的提示词，而会来自：

一套可被 agent 执行的设计规则。

所以你要是生成的效果不理想，自己多看看这三步是否做到了。另外通过两次 MCP 更新，能得出最清晰的一条线：

2 月是在说，code 和 canvas 可以来回走了；
3 月是在说，agent 现在可以直接在 canvas 里工作了。

而这背后的真正变化其实是：

设计稿，开始从“结果文件”变成“生产环境”。

👉 安装 skills

如何打开新版 MCP:

1.随便打开文件 - 进入开发模式

2. 点击右侧 Enable desktop MCP server

3. 选择你用的 IDE 软件，点击 “add” 添加，如果里面没有你用的，点击“Other editors” 复制 Code snippet 直接发给你的软件，例如我用的 Codex，发给它，它自己会链接好。

‼️‼️‼️

‼️很多人到这里就停了，然后会觉得：

“为什么生成的还是一团乱？”

因为你少了最关键的一步：

👉 安装 skills

你可以理解成：

MCP 是“让 AI 进来”
Skills 是“教 AI 怎么干活”

官方推荐的方式是：

在你的项目里准备一个类似这样的结构：

/skills

里面写清楚：

  • 页面结构怎么搭
  • 必须用哪些组件
  • spacing / color 怎么用
  • 哪些行为是禁止的

如果你是第一次玩，可以先用一个最简单版本：

👉 比如：

  • 所有 UI 必须用现有 components
  • 所有颜色必须来自 variables
  • 必须使用 auto layout
  • 不允许写死 padding / color

就这几条，效果都会明显提升。

最后一个非常关键的提醒（很多人会踩坑）

你一定要记住一件事：

❌ 不是“连上 MCP 就能用好”
✅ 而是“设计系统 + skills 决定最终效果”

但如果你做到这三件事：

  • Figma 里有完整组件体系
  • variables（token）结构清晰
  • 有基础 skills 规则

那你会明显感觉到：

Codex 开始“像你团队里的设计师一样干活”了

使用 Figma MCP 前，有几个关键限制需要搞清楚：

1）不是无限调用，而是按权限分级
Figma MCP 有明确调用额度，且主要限制在“读取设计上下文”（组件、变量、布局等），并不是所有写操作都计入次数。

2）不只是总量限制，还有速率限制
除了每天/每月调用次数，还有每分钟请求上限，连续高频使用很容易触发限制。

3）权限取决于“文件所在团队”，不是你个人账号
即使你是 Pro，如果文件在免费团队中，仍然按免费额度计算，这是最容易踩的坑。

4）不同套餐差异很大

  • 免费版 / 只读：每月约 6 次，仅能体验
  • 教育版：跟随 seat 权限，无额外加成
  • 专业版（Pro）：约 200 次/天，可正常使用
  • 企业版：更高额度，适合重度 AI 工作流

Figma MCP 不是“能不能用”，而是“你能用到什么程度”，是 Agent + 设计系统 + skills。
