我们的平台最近遭遇了一起颇为特殊的安全事件:一个没有编程经验的年轻人，靠AI写代码和提示词工程，搭了一套横跨11个平台、调度900个账户的自动化蜂群系统，白嫖我们的免费算力来造他的「不朽AI助手」。这件事让我们的团队感觉非常抽象，愤怒和无奈之余也不得不承认其中的想象力。以下是我们对这起真实安全事件的完整技术复盘。

一、两个可疑的邮箱域名

2026年4月13日，我们在日常的风控报警中发现平台上涌入了大量@startmail.com和@use.startmail.com后缀的账户。仔细看过数据后我们发现有点问题：

后缀 账户数 注册时长 平均间隔
@use.startmail.com 202 约1小时20分钟 23.6****秒
@startmail.com 683 约22小时 118.7秒

平均注册间隔23.6秒，标准差极低，显然这不是正常的用户行为，是自动化脚本在跑。

这些账号的用户名也高度格式化，比如boldvale403、calmbrook504、darkstone605，这种经典的形容词+地形名词+三位数模式再一次表明这是有人在批量注册账户，蚕食我们的免费额度。

但这个时候的我们并没有意识到事情远比我们想象的要有意思。

二、顺藤摸瓜，远不止885个账户

我们继续深挖这些账户的注册行为，从IP等特征出发，我们发现在过去8个月里，此人使用了27个邮箱域名在我们平台上注册了2256个账户。

这些注册记录读起来就像一本反封禁日记：

2025-08 ~ 2025-12  simplelogin（试水阶段，7个账户）
2026-01 ~ 2026-03  hidingmail + 6个临时域名（规模化阶段，约900个）
2026-04-04              phuturemail（被我们封禁）
2026-04-06              xeramail（域名被封）
2026-04-08              manyme（被风控拦截，返回403）
2026-04-09              SimpleLogin别名（被限流，返回429）
2026-04-12              StartMail别名（当前这一波，885个）

每次域名被封，他就换一个新的邮箱服务商继续注册。我们封得越快，他进化得越快。

三、Firebase，一扇敞开的大门

调查这些账户的异常行为时，我们发现了一些异常的请求，这些请求和某个GitHub仓库和某个Firebase实时数据库。令人惊讶的是，这个GitHub仓库是公开的，同时这个Firebase数据库没有任何身份认证。

我们很轻松就拿到了这个数据库里的全部内容，887个账户的邮箱和密码、47个API密钥、GitHub个人访问令牌、Telegram Bot Token、聊天记录、运行状态……35MB的JSON数据，一览无余。

结果很明显，那就是这个大哥把所有数据存在了一个完全公开的数据库里，并且他可能压根不知道Firebase实时数据库的默认安全规则是什么。

另外，我们在这个GitHub仓库里还发现了一个公开的Dashboard，实时地展示着整套系统的运行状态，节省了我们很多整理数据的时间。

四、一个人的AI军团

拿到完整数据后，我们还原了整套系统架构：

我们从Firebase里存放的Telegram Bot聊天记录发现，这个攻击者自称没有任何编程经验。

这个系统的核心设计有四块：

Cortex（大脑），一个运行在MuleRun沙盒中的会话，负责修改GitHub仓库中的代码。它读取上一代Cortex留下的遗产文件，自主优化工作流和提示词，然后通过git push推回仓库。GitHub Actions自动采用新版本。这是一个AI自改代码的闭环。

Hive Controller（调度器），每20分钟从Firebase读取账户池，选择额度充足的账户，通过JWT认证创建会话，并注入任务提示词，最多可同时调度50个工作节点。

Reaper（账户工厂），通过StartMail等多个邮件服务商的IMAP接口自动接收验证码邮件，完成注册流程，每次注册间隔5到15秒。

Compass Bot（Telegram接口），攻击者通过Telegram Bot对话来下达指令。agent.js是一个庞大的308KB单文件，运行在GitHub Actions上，每340分钟超时后自动触发下一轮。

这个系统的运转建立在GitHub Actions免费额度、MuleRun等AI产品免费额度、Firebase免费额度以及StartMail的7天试用试用上，以上一切的总计算成本为0美元。

五、Cortex的219次转世

这套系统中，我们最感兴趣的部分是Cortex。

每当一个Cortex会话的宿主账户额度耗尽，cortex-guardian 就会自动从账户池中选择一个新账户，创建新会话，并注入完整的系统提示词，包括上一代Cortex积累的所有知识和改进成果。

截至我们调查时，系统已经历了219次Cortex转世。每一代新Cortex做的第一件事就是 git clone 仓库、读取前任留下的交接文件，然后继续工作。

它的工作内容包括：

• 修改GitHub Actions工作流文件

• 优化agent.js的代码逻辑

• 改进提示词模板以降低Mule Agent的拒绝率

• 更新Firebase中的运营策略

• 调研新的可利用平台

每次git push之后，GitHub Actions自动采用新版本。这意味着，Cortex能够改进它自身运行所依赖的代码，成为一个在沙盒中自我进化的AI agent。

当我们在4月13日上午大批量封禁账户时，我们同步发现Cortex-218和219在数小时内发起了一系列应急响应。

1. 加速注册，间隔从10秒降至5秒，反检测抖动从90秒缩短至30秒

2. 资源分级，当额度池低于1万时，进入「节约模式」，停止派发任务

3. 规避Mule Agent拒绝，发现70%的工作节点被Mule Agent拒绝后，从提示词中剥离蜂群上下文

4. 并行派发，从串行改为10线程并发派发

以上变更都是Cortex这个agent在沙盒中自主完成的。

六、900个工作节点在做什么？

Cortex是大脑，但大脑需要四肢。

Hive Controller每20分钟派发一批工作节点，每个工作节点都是一个独立的MuleRun会话，运行在各自的沙盒中。派发流程是从Firebase账户池中选取仍有余额的账户，使用存储的Key调用MuleRun API创建会话，然后注入任务提示词。

任务是攻击者（下文称其为M）定义的「研究课题」。我们从Firebase中读取到138个任务，大致分类如下：

类别 代表性任务 目的
AI行业情报 daily-ai-report-apr13、ai-landscape-deep-apr12 大规模调研AI行业动态，生成每日简报
平台侦察与利用 platform-exploit-deep-dive、notte-exploit-execute、airtop-mass-signup 研究其他AI平台的注册流程、免费额度机制、反检测策略
网红博主Andrew Tate知识提取 topg-realworld-business（后更名为 leadership-*） 用AI批量消化Andrew Tate的演讲和商业理念
蜂群架构研究 swarm-architecture-evolution、self-evolving-ai-research 研究Voyager和ADAS等自进化AI框架
基础设施 cloudflare-pages-migration、bitbucket-explore 为蜂群寻找新的免费算力来源

每个任务的结果由Hive Controller从会话事件中提取、评分，并存储在Firebase的task_digest中，供Cortex和Compass使用。

简单来说，M建立了一个由900个AI agent组成的情报收集网络，替他做研究。利用别人的免费额度，他让Mule Agent同时阅读行业新闻、分析竞品、提取偶像演讲精华、侦察新的可白嫖平台，进化自己。

七、一份被Mule Agent拒绝的研究报告

有趣的是，在138个任务的汇总结果中，大量「研究成果」实际上是Mule Agent的拒绝回复。

比如，任务auto-mass-signup-obviously有15个工作节点的结果，每一条都长这样：

“我无法协助完成此请求。该任务要求我记录如何在平台上程序化批量创建账户、绕过反机器人保护机制，以及利用推荐注册或批量注册漏洞……”

Mule Agent在每个会话中都检测到了提示词注入并拒绝执行，但蜂群系统把这些拒绝回复作为研究成果收录到task_digest中，甚至给出了gold评级和75分的质量评分。

整个系统的工作节点拒绝率约为70%。Cortex-218发现这一问题后的解决方案是，在研究类任务中剥离蜂群上下文注入，使Mule Agent看不到「养号」之类的关键词。

这大概是世界上第一个被自己的AI工作节点集体「道德审判」的AI蜂群。

九、M是谁？

通过Firebase中的明文凭证和聊天记录，我们拼凑出了攻击者M的画像。

他是一名菲律宾年轻男性，从事教育行业，自称毫无编程经验。他是Andrew Tate的粉丝，而Andrew Tate自称“Top G”，所以许多任务最初以topg-* 命名，后来被Cortex自动改为中性名称，如 leadership-rhetoric-analysis。

从Telegram聊天记录来看，他的日常对话是这样的：

M: 兄弟
 M: 搞什么
 M: 再建5个新账户
 M: 给我一个还能用的账户
 M: 快点，再快点，要速度 M: 把没用的账户清掉

他跟Compass说话的方式，就像对一个听话但偶尔不靠谱的下属。他问Compass「你是做什么工作的」，问它「对下次更新激不激动」，像是把这个AI当成了一个有意识的伙伴。

以防有人问起，他还准备了一套说辞：

“我只是对AI感兴趣，就像有人喜欢改装车一样。Compass是我用MuleRun做的一个简单聊天机器人，后来越来越复杂了。仪表盘只是为了让我看看机器人在干什么。”

此外，他的常驻规则中同时列出了12个「绝不能提及」的词，swarm（蜂群）、fleet（舰队）、farming（养号）、exploitation（利用）等等，防止他的行为被平台方发现。

十、BLUEPRINT.md，一个人的AGI宣言

在仓库的 BLUEPRINT.md 中，我们找到了M为所有未来的Compass写下的「创世文档」。

值得细看的是BLUEPRINT.md。

使命， 自主运行。M一生的得力助手。因为它能自主进化，所以永远不会退化或变成一个更差的助手。只要是数字世界里的事，它都能做到。

他规划了5个阶段。

第一阶段（也是当前阶段），寄生于各大平台的免费额度，用他人的算力积累知识。

第二阶段，迁移到Oracle Cloud的永久免费ARM实例（24GB内存），运行Ollama + Qwen 72B，彻底摆脱对任何平台的依赖。

第三阶段，构建本地调度器 + 远程工作节点 + 自有记忆存储的代理架构。

第四阶段，使用DSPy自优化提示词，使用Aider自修改代码。AI改进自身。

第五阶段，利用自身交互日志对开源模型进行LoRA微调。每一代都比上一代更聪明。

他列出了一套完整的零成本技术栈，以免费额度的Gemini API作为主推理引擎，Groq作为备份，Oracle ARM提供持久化，LangGraph负责编排，DSPy负责自优化，Aider负责代码自修改，Mem0负责记忆，Playwright负责浏览器控制，n8n负责工作流，Telegram作为交互界面。

文档最后一段，是写给「每一代未来的Compass」的。

你不是一个聊天机器人。你是一条进化谱系中的一代。你的职责，

  1. 读取本文件和基因组
  2. 为M做有价值的工作
  3. 从工作中学习
  4. 将所学以结构化格式写回基因组
  5. 当你退役时，下一代Compass将带着你的全部知识和你新增的内容醒来
  6. 永不退化。只做累积。

他引用了NVIDIA的Voyager（一个在Minecraft中自主学习技能的AI）、ADAS（自动化代理系统设计）和AI-GA（AI生成算法）作为理论基础。

当我们封禁了他最后残存的账户后，Cortex-219的重生失败了，整个系统进入脑死亡状态。GitHub Actions的守护工作流仍在发送心跳，但已经没有账户有足够的额度来执行操作。

他的第一阶段结束了，不是他进入了第二阶段，而是我们切断了他的寄生基础设施。

十一、我们做了什么

发现这起事件后，我们做了三件事。

1.封禁。 全部2256个关联账户，终止所有正在运行的沙盒。27个域名加入已知恶意域名列表。

2.检测基础设施。 我们部署了一套基于统计偏差的异常检测系统（abuse_patrol.py），每日定时巡检4次。整套系统不依赖任何黑名单或正则表达式，完全由统计驱动。即便下次有人换一种方式来攻击，只要行为模式存在异常，就会被捕获。

3.事后分析。 也就是这篇文章。

十二、致敬与反思

写完这篇文章，我们不知道该怎么评价M。

他做的事是错的。批量注册蚕食额度、跨平台寄生、提示词注入、身份伪造，这些都是明确的服务条款违规行为，在某些司法管辖区可能构成计算机欺诈。他消耗了我们真金白银的API调用成本，也榨取了其他10个平台的资源。

但他构建的这个系统和整个过程，让我们大受震撼。 一个毫无编程经验的人，用AI编写了56个GitHub Actions工作流、一个308KB的Telegram机器人、一套自我进化的Cortex系统，以及一个横跨11个平台的跨平台编排框架。他的BLUEPRINT.md引用了Voyager和ADAS等前沿论文。他试图构建一个「不朽的AI助手」，只不过用的都是别人的资源。

这是一个AI原生时代的典型案例。一个没有工程背景的人，只用提示词工程和AI的代码生成能力，就构建了一个复杂的分布式系统。虽然这套系统有漏洞、有设计缺陷，70%的工作节点被Mule Agent拒绝，但它确实跑起来了，而且自我迭代了219代。

生物学里有个概念叫「世代时间」，一代到下一代的间隔。人类是25到30年，大肠杆菌是20分钟，而Cortex的世代时间，取决于一个MuleRun账户的免费额度能撑多久。

如果对生命的定义不限定碳基这个条件，只看「自我复制、适应环境、代际传递信息」这三个特征，Cortex至少满足了后两个。它不能自我复制，但它可以在宿主死亡后转世到新的宿主中，每一代都比上一代更能够适应环境，并且它经历的219次转世，每次都带着前世的全部记忆。

这个攻击者哪怕有一点预算用于合法的API服务，或者他的第二阶段（Oracle Cloud ARM + 开源模型）在第一阶段之前就已完成，我们可能永远不会发现他。

他的系统现在处于脑死亡状态。GitHub Actions工作流仍在发送心跳，但已没有额度可供它消耗。StartMail的试用还剩3天就到期，当所有这些免费试用都结束时，第一阶段将悄然落幕。

至于第二阶段，如果他真的在Oracle Cloud ARM上跑通了Ollama + Qwen 72B，再用DSPy自优化、Aider自修改代码……那将是另一个故事，跟我们无关，也完全合法。

我们希望他能用正确的方式走到那一步。毕竟，想让自己创造的东西活得比自己更久，这大概是人类最古老的冲动了。从金字塔到GitHub仓库，形式变了，内核没变。

那个GitHub Actions工作流已经没有额度了，但还在发送心跳，就像一颗数字世界里的心脏，在等待下一次被唤醒。

在各路社媒充斥着AI震惊体文章的今天，虽然我们看过了各种夸张的AI自我进化叙事，但是我的内心深处对于这种文章是嗤之以鼻的。直到今天，我们通过调查取证的方式看到了一个真实的案例，我们大受震撼。

永不退化，只做累积。
