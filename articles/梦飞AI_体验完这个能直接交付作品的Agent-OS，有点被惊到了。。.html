推荐和用过不少 Agent 产品后，发现大家有一个共同感受：

食之无味，弃之可惜。

Agent确实能自主规划和调用工具，也能干活。就是真正交付出来的结果，往往总差一口气，要么意图理解跑偏，要么执行路径不准，缺乏真正的专业度。

越来越发现，做 Agent 的终极壁垒：是行业Know How。

从「能用」到「好用」隔着一条叫做「专业」的鸿沟。

这两天朋友给了我一个邀请码，推荐我试了一个叫做 OmniWork 的产品。

真正体验之后，我发现它和很多通用 Agent 产品不太一样，它感觉更像是全能版的知乎专家，尤其是做完第一个任务，惊讶到我了。（相信我，我真的我没有故意震惊体。。大家看下测试案例）

（https://www.omniwork.ai/）

先不说上手用，就光看到了模型选择表，我对他都已经有一种预判了。

支持的模型都是全球一流模型，我猜，这是因为好的专家经验必须配上全球最顶尖大脑。

平台目前内置了 19 个专家智能体，虽然数量听起来不多，但每个专家（Expert）都资历不浅，都是围绕具体创作岗位设计出来的专业 Agent。

就比如：像电影制作导演专家：

它是由 OmniWork 与上戏文化，也就是上海戏剧学院产学研实践平台共同打造的。

而音乐专家，则是由 OmniWork 官方与上海音乐学院人工智能音乐疗愈重点实验室联合打造。

这意味着，OmniWork 不是简单给模型披了个专家外壳，而是在把真实行业里的判断标准、工作流程和专业经验，封装进不同的专家 Agent 里。

更关键的是，OmniWork 不只有“专家”，它还配了上百个 Skill（技能）。

如果说专家（Expert）更像“人”，那么 Skill 更像这个人掌握的方法论和工作流。当专家能调用具体 Skill，任务就不再停留在建议层，而是可以一步步进入执行层。

这十几个专家加上百个skill的组合，就成了一套可以灵活组合的创作协作系统，衍生出数百种玩法。

如此一来，OmniWork就能做到，给它一个目标，它就能组织专家 Agent+可执行skill，把任务持续往前推，直到交付结果。

所以没有拿几个简单任务去试，而是直接给了它几个比较复杂的目标，他给出的结果真的出乎意料：

Case 3：把演讲稿做成PPT

前面两个案例，一个是游戏，一个是虚拟偶像，都偏创作型任务。

但毕竟对大多数人来说，每天真正消耗时间的，不一定是做一个多酷的创意项目，而是整理材料、提炼结构、做汇报、改 PPT 这些琐碎但必须完成的工作。

所以，我也有尝试更日常的场景：做PPT。

我把我上一次去2050的演讲稿交给了PPT 设计专家Agent，让他帮我做成PPT：

这个任务看起来不复杂，但其实很考验系统能力。

真正好的 PPT，需要先理解内容主线，判断这份演讲稿到底在讲什么，哪些内容是主观点，哪些内容是支撑案例，哪些内容适合做成结构页，哪些内容适合做成结论页。

然后再进入页面设计和视觉表达，下边是最终完成的部分PPT：

（上线滑动查看）

这个 case 没有前两个那么酷，但我觉得很重要。

因为真正能进入日常工作流的 Agent OS，不能只会做大型创意项目，也要能处理这些高频、琐碎的任务。

除了这些即时任务，OmniWork 还有一个很值得关注的能力：Autowork。

它可以把一些任务设成长期运行，比如定时监控某个话题、追踪竞品账号、整理行业动态，这种 7×24 小时的自动化运行，对内容创作者来说，这类能力非常实用。

写在最后

体验完这几个任务后，我对 OmniWork 的感受和定位更清晰了：

OmniWork 是一套面向创作任务的 Agent OS。

它不只是在提供专家Agent，他真正做的是给这些专家提供了一套稳定协作的环境。

在这个环境里，主 Agent 负责理解目标、调度专家；不同 Expert 负责各自专业环节；Skill 像工具一样被嵌入执行；而持久记忆则保证了它越来越懂你的风格。

与大多数产品一样，在内测的体验过程中并不是完美的，比如长时间的等待、比如偶尔的状态无反馈、比如任务中断，但是瑕不掩瑜，相信这些小问题会在上线前补足。OmniWork 真正值得关注的是：

提供了一套完善的工程环境，很好地处理了多专家之间的协同、上下文的传递、任务中断之后的连接，以及记忆与目标机制，让这些专家智能体能够在这个环境中非常顺畅、丝滑的围绕同一个目标执行。

一个任务Agent想推进到交付，只有专家不够，只有环境也不够。

OmniWork尝试把“行业知乎专家”和“强大的执行环境”结合在一起，让我们看到Agent 有机会从试玩工具，真正走向可交付系统的路径。

一次很有趣的体验。
