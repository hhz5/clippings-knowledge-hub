Context 才是唯一的壁垒

我用 CLI 把"心里的话"变成了一条可执行的内容生产线

好朋友橘子昨天写了篇文，写的很好：

 Context 是唯一重要的事情。 Context 不在你的小红书里，不在你的即刻里。 Context 在你的微信里，飞书里，电脑里。 但其实那些也远远不是全部。 最重要的 Context 其实是在你的心里。 是你对世界的认知，对关系的感知，对事物的判断。 那是你独一无二的灵魂。 

他的提炼和表达非常的到位。正好最近我在做一件事情，和他讲的不谋而合。

展开前先说个数据：同样质量的一篇文章，我用传统方式（打开 AI 对话框来回改 Prompt）大概需要 120-240 分钟。用我接下来要讲的这条管线，25-40 分钟，而且我自己动手的时间不超过 15 分钟。

省下来的时间不是偷懒——是把时间从"和 AI 拉扯"转移到了"注入我的判断"上。这种感觉很像过去你在自己弹奏，现在你在指挥。

这篇文章和大家分享下如何用最近很火的Cli来把审美变成可执行的内容生产线！

01

PART

你的 AI 为什么总写不出你要的东西？

你大概经历过这个场景：打开 ChatGPT 或 Claude，输入一段 Prompt——"帮我写一篇关于 xxx 的公众号文章，要有深度，有案例，语言生动一点……"

然后等。有时候出来还行，更多时候你觉得"差点意思"。于是开始改——"再口语化一点"、"加个数据"、"开头换个钩子"……折腾半小时，最后要么凑合发了，要么还是自己重写一遍。

问题到底出在哪？

不是模型不够好。Opus 4.6、GPT 5.4，能力都够强了。也不是 Prompt 不够精，你加了约束、给了示例、甚至塞了几千字参考材料。

问题是：你的 AI 没有足够的 Context，也没有你的审美。

它不知道你上周写过类似的文章、风格是什么样的。不知道你的读者是有行业经验但不懂代码的人。不知道你收藏过哪些好文章、你觉得什么样的表达叫"好"。不知道你对这个话题的真实判断是什么——哪些观点你认同、哪些是废话。

它在一个真空环境里凭空创作。一个再聪明的人被关在没有任何信息的房间里，也只能说出正确但空洞的废话。

橘子那句话点破的就是这个：Context 在你心里——但 AI 读不到你的心。

所以我前阵子一直在做一件事：把心里的 Context 外化成一条 AI 能读得懂的管线。

这套方法适合谁？

适合已经有稳定内容输出习惯的人。

如果你一周写不了一篇，问题不在于工具链而在于要不要写、写什么。

这套方法解决的是**"已经决定要写，怎么写得更快更好"**。

另外文中会用到命令行工具（CLI），不会用也没关系——核心思维一样，结尾会给降级方案。

下面我从IPO三个角度拆解这套写作工作流：

02

PART

Input 层：把散落的 Context 汇聚起来

我的 Context 主要散落在两个地方。

飞书 — 我自己的知识库。过去写的所有文章、课程、决策文档……加在一起就是"我是谁"的数字化版本。

以前写新文章要在脑子里翻："我以前写过类似话题吗？当时怎么说的？那个数据在哪？" 效率低还经常漏。

现在一句话让 AI 去翻：

帮我找到和Skill相关的飞书云文档

拉出所有相关文档，挑几篇拉全文，AI 瞬间获得"我在这个话题上想过的所有东西"——不是几百字摘要，而是完整原始素材。

YouMind — 我手动收藏外部优质内容的地方。好的文章、好的数据、好的表达方式，我会收藏进来。这些收藏不是资料库，它们是我的审美和判断的投影——我收藏的东西 = 我看重什么。

帮我在YouMind里找到和Skill相关的内容,罗列出来,每篇都简单介绍下内容是什么

Input 层做的事就一件：把"飞书里的我"和"YouMind 里的视野"同时喂给 AI。 这时候 AI 已经不是空脑袋了——有了知识基础，有了筛选过的参考素材。但它还缺最重要的东西。

03

PART

Process 层：把"心里的判断"变成多轮可执行的指令

这是整条管线最关键的一层。也是绝大多数人完全缺失的一层。

橘子说的"Context 在你心里"——在写作场景里指的是什么？是你知道章节该什么顺序读者才跟得上。知道哪里该用大白话哪里可以来点专业感。知道哪个数据比另一个更有说服力。知道结尾用什么力度才能让人记住而不是划走。

这些东西没法写成一条 Prompt。

它们不是一个指令，是你的审美、经验、直觉在同时运作。

我怎么传递给 AI？答案在Claude Code的终端打开的知识库里，在飞书云文档的评论里！这整个过程是人机协作的过程，非常美妙！

这样Claude Code默认 就自带了黄叔的认知和审美，然后再叠加下面的路径：

Process 不是"写完稿改一遍"，而是从骨架到血肉的全程人机协作，一个三层递归结构。

📌 配图位置：Process 三层递归结构示意图（骨架 → 血肉 → 全局校准）

第一轮：骨架碰撞 — 决定先后、详略、边界

我不会让 AI 直接开始写正文。先让它基于飞书里的素材生成参考提纲，然后我开始批注（比如）：

"顺序反了。应该先讲'为什么你需要'（痛点），再讲'是什么'（概念），最后才讲'怎么做'（实操）。现在直接跳进实操，读者跟不上。" 这条背后是我的判断——你得先让人觉得有问题，再给解法。 

"缺一整块：冲突检测和版本管理。这是实际使用中最高频的痛点，用户反馈里反复提到过。去飞书找一下那次社群讨论的记录。" 这条背后是对"真实痛点"vs"我觉得重要"之间的区分能力。前者来自用户反馈，后者来自我自己。 

这些批注的本质是在做决策，也是你审美的体现。 

AI 可以基于我的认知先生成一版及格提纲，但只有我知道什么顺序能让读者看得下去、什么该浓墨重彩。

然后，执行交给AI：Claude Code可以基于飞书云文档的评论去调整内容！

第二轮：逐章打磨 — 校准开头、数据、用词、节奏

提纲定了，一章一章来写，每章都走一轮批注。颗粒度从章节级降到了段落级：

"开头太平了。用一个场景切入——'你打开 Claude Code 输入一段 Prompt 等了三十秒拿到不错的回复。然后呢？下次遇到类似问题你还是从头开始。' 让读者瞬间代入。"

"'提升效率'这个词出现了三次，换掉两个。用具体的场景描述代替抽象词汇。"

你会发现有些批注甚至在指挥 AI 回到 Input 层去拉新数据——比如"换成 Skill Hub 最新扫描结果"。Process 和 Input 不是串行的，它们在交互。这是一个活的循环，不是死的流水线。

第三轮：整体校准 — 消除重复、统一主线、对齐风格

所有章节写完合在一起，跳出单章视角做全局批注：

"第二章和第五章都在讲'Agent 思维'但有大量重复。保留第二章定义部分，第五章只留实战案例。"****"全书缺一根贯穿的主线。现在像五篇独立文章拼在一起。埋一条线——'从使用者到设计者'——每章结尾回扣。"

轮次 颗粒度 我在做什么
骨架 章节级 先后顺序、详略分配、边界划分
血肉 段落级 开头、数据、用词、节奏
全局 全书级 消除重复、统一主线、风格对齐

每一轮都是同一个模式：AI 给出框架或内容 → 我注入判断 → AI 执行我的判断。

而这些判断来自我写了几百篇文章、做了几十次直播、和上千个用户聊过天之后积累下来的直觉。橘子管它叫灵魂，我管它叫 Process 层。

关键是这每一层都可以被 AI 读取和执行——评论写在飞书文档里，CLI 拉出来传给 Opus：

读取这篇文档的评论，并且根据评论进行修改。

AI 拿到的不再是模糊的"写得更好一点"，而是一条条带着上下文的具体校正指令。

我不得不再夸一次Skill，Claude Agent Skills完全可以逐步把上面人的判断变成Skill，从而上面整个Process会越来越少有你的参与。

04

PART

Output 层：让最对的厨师来炒菜

Input 有了素材，Process 有了判断，最后选谁来执行。我用 Claude Code + Opus——文字质感、理解深度、处理复杂指令的能力最匹配我要的风格。

但注意：我不是让它创作，我是让它合成。 它不需要凭空想观点（Input 给了），不需要猜我喜欢什么风格（Process 给了）。它只需要做一件事：按我的判断整合成通顺的内容。

📌 配图位置：厨师炒菜比喻图（菜篮子 + 菜谱 + 厨师）

飞书 + YouMind = 菜篮子（食材）
我的批注 = 菜谱（怎么做、什么口味）
Opus = 厨师（执行烹饪）

厨师不需要会种菜也不需要发明菜系。只需要拿到好食材照着菜谱炒出一盘好吃的。

包括这里面可以调用YouMind的各种Skill，比如我做了个信息图，能参考我个人形象出图片，咱们这篇文章就完全是用YouMind的生图Skill来跑的，我已经提前在YouMind里配置好了，CC直接调用就好。

05

PART

完整运转一次给你看

假设选题是**"为什么大多数人用不好 AI 写作？"**，完整流程：

**Step 0 — Input：**从飞书拉取历史相关内容（8 篇），从 YouMind 搜索外部参考，从黄叔知识库获得我的认知。

**Step 1 — 定骨架：**Opus 基于素材生成提纲 → 放进飞书 → 写 3-5 条结构性批注 → 提纲定稿。

**Step 2 — 逐章填充：**按提纲逐章生成，每章一轮表达性批注 → 所有章节定稿。

**Step 3 — 全局校准：**合稿后做跨章节批注（消除重复、统一主线、对齐配图）。

**Step 4 — 最终合成：**把所有批注拉出传给 Opus 做最终整合。

Step 5 — 推到公众号：这一步先手动了，毕竟最近似乎风声比较紧。

全程 25-40 分钟。我自己动手不超过 15 分钟——主要是写批注。

剩下的是 CLI 和 AI 在跑。

06

PART

为什么这件事值得讲

值得讲的是背后的思维变化。

大多数人对 AI 的使用还在第一阶段：我问，AI 答。

少数人到第二阶段：我给详细 Prompt，AI 给更好的答。

但几乎没人到第三阶段：我搭一条管线，AI 是其中一个环节。

第三阶段的变化在于：你不再是一个使用者，你变成了架构师。 你设计的不是单次对话，而是信息流动的方式。

橘子说的 我的管线
Context 在飞书、微信、电脑里 Input：飞书 CLI + YouMind CLI+黄叔知识库
最重要的 Context 在你心里 Process：飞书批注 = 判断的多轮外化
那是你独一无二的灵魂 Output：Opus 合成 = 灵魂 + 效率

今天就能做的三件事

不管你现在用什么工具写内容，都可以从这三步开始：

1. 建一个"素材篮子" — 不一定用飞书，任何你能快速检索的地方都行，比如有些人喜欢用Obsidian。把你过去写过的东西、收藏的好内容放进去。下次写新文章之前先翻一遍，比凭空写强十倍。（注意，黄叔后面还会延展，这个素材篮子其实就是构建内容管线的知识库）

2. 写批注代替改 Prompt — 下次 AI 给你初稿时，不要在对话框里说"再改改"。把初稿放到任何能写评论的地方（飞书云文档的评论），像审稿一样逐段写你的判断。然后把所有批注一次性丢给 AI。

3. 让每个工具只干它最擅长的事 — 不要指望一个 AI 完成所有事。找会画图的工具画图，找会搜索的工具搜索，找一个文字最强的做最终整合。你不是在找最好的工具，你在搭最好的流水线。

Context 确实是在心里的。

但如果你能把心里的 Context 变成一条可执行的管线，

那你就不再只是一个人在写内容——你是一个系统。

而这个系统产出的每一篇内容，都有你的味道。
