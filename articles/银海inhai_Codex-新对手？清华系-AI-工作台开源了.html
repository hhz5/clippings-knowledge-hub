清华 THUNLP、面壁智能、OpenBMB 和 AI9stars 最近开源了一个 AI 工作台，叫 PilotDeck。

它不是普通聊天框，也不是单纯的代码编辑器。

打开之后，左侧是不同项目的 WorkSpace，中间是当前项目的对话和执行区，旁边能看到文件、记忆、成本、模型路由。

我们可以同时开几个工作舱，让它们各自跑不同任务。

项目 GitHub：https://github.com/OpenBMB/PilotDeck

官网地址：https://pilotdeck.openbmb.cn/

我这两天试下来，最直观的感受是：它适合同时管理几个 Agent。

比如我先把 PilotDeck 自己的 GitHub 链接丢进去，让它给这个刚开源的项目做一次完整宣发。

需求很直接：官网、README、中文介绍、英文介绍、社媒文案、首图、教程、开发者社区话术，全部准备好。

它基本把整套方案都搭出来了：先读项目，整理核心卖点，再拆成不同受众的表达。

视频详情

40分钟的视频，直接转写、摘要、金句、多语言版本、小红书标题、短视频脚本，一起往外出。

还有一个工作舱在写短剧，设定是“记忆可以被公司按月订阅的城市”，它负责世界观、人物关系、三集大纲和第一集剧本。

要求也很俗，但很实用：能在浏览器里打开，能操作，有倒计时，有输赢状态，最好画面能截图发出来。

视频详情

我以前用聊天框做这种报告，最怕两件事：第一，资料越聊越乱，后面不知道哪个结论来自哪里，第二，成本不可控，明明只是整理表格，也在用贵模型一路跑。

PilotDeck 在这里有两个点挺有用。

一个是文件和记忆都跟着 WorkSpace 走。

资料库、分析表、报告草稿、最终 HTML，都在同一个项目舱里，不会和别的任务混在一起。

另一个是智能路由。

简单的资料清洗、格式整理、标题改写，可以走轻模型，复杂判断和结论，再交给强模型。

它不是简单喊一句“省钱”，它可以把 token 花在哪里、哪个任务用了什么模型、每个 WorkSpace 成本多少，都摆出来。

这个东西对长程任务很重要。

因为 Agent 真正贵的地方，往往不是问一次，而是我们让它在后台跑一整晚。

报告做到最后，我还试了一个更贴近真实交付的用法：结合报告类 Skill 去做做统一润色，PilotDeck 提供了整体的技能管理能力，也是可以跟着项目走。

前面先让 WorkSpace 把资料、分析表和初稿沉淀下来，最后结合“Claude 风格研究报告”或“投研简报风格”的 Skill 去生成最终版本。

标题、结构、段落密度、图表说明都会被统一处理，出来的东西更像一份能直接发给人的报告，而不是一堆中间产物拼在一起。

第三个任务，我故意跑了一个很容易乱的：短剧创作。

设定是这样的：在一个记忆可以被公司按月订阅的城市里，有人突然想找回自己十年前删掉的一天。

我让它做三集短剧开发案，包括世界观、人物小传、人物关系、三集大纲、第一集剧本和关键分镜。

这个任务最容易暴露普通 AI 的毛病。

前面说记忆只能本人订阅，后面突然让另一个角色随便查看，第一集主角怕水，第二集又让他毫无障碍跳进海里，前面设定公司很封闭，后面又写成人人都能进的商场。

Codex 新对手？清华系 AI 工作台开源了

AI产品银海

视频详情

长周期创作怕的不是写不出来，怕的是写着写着自己打架。

PilotDeck 的项目制记忆能把这些设定放进一个比较稳定的地方。

世界观规则、角色秘密、禁忌、风格偏好都在这个剧本 WorkSpace 里，Dream 在空闲时还会整理记忆，如果整理错了，也能回滚。

我不敢说它能直接写出神剧本，但它很适合做“剧本开发桌”。

人设、设定、分集、分镜、审稿意见都在同一个项目里，比散在十几个聊天窗口里强太多。

PilotDeck 不是偷偷把一个任务拆成一堆我们看不见的小步骤，而是让我们把不同工作线程放在桌面上同时跑。我们知道哪个舱在做什么，也知道每个舱的文件、记忆和成本。

最后一个任务，是视频解析。

普通 AI 总结视频，往往给我们一份大摘要。

但现实里，同一场发布会，不同人要的东西完全不一样。市场部要传播金句和高光片段，产品经理要功能表和待跟进问题，老板或者投资人要商业判断。

所以我开了几个并行 WorkSpace，上传视频链接之后，它直接能够调用对应的 whisper CLI能力去理解我们这个 40 多分钟的视频。

它一开始判断没有办法直接一下子理解完 40分钟的视频，于是它智能地做了时长切分成四个片段。

传播舱负责提炼 10 个适合短视频的片段，然后结合时间戳、标题、字幕和封面字，去更好的理解这个视频的内容。

然后别的产品舱负责整理功能点、用户价值、使用场景和待跟进问题。商业分析舱负责看定位、竞品、商业模式和风险。

最后结合报告整理类 Skill，把三份材料生成三种版本：给市场团队的传播包，给产品团队的复盘表，给投资人看的简报。

这里最能体现「并行线程」这件事。

PilotDeck 不是偷偷把一个任务拆成一堆你看不见的小步骤，而是让你把不同工作线程放在桌面上同时跑。

你知道哪个舱在做什么，也知道每个舱的文件、记忆和成本跑完这几个任务，我对 PilotDeck 的理解简单了很多：它把 Agent 的工作边界从“一个对话”换成了“一个项目”。

一个项目一个 WorkSpace，每个 WorkSpace 里有文件、记忆、用户偏好和成本账本。

我们可以同时跑游戏、报告、播客、剧本、视频解析。

它们互不污染，但都在同一张桌面上，想看细节，就点开某个舱，想看钱花到哪里，就看成本，想改它记错的偏好，就进 Memory。

我尤其喜欢它把「记忆」做成白盒这件事，现在很多 AI 产品都说自己有记忆，但大多数时候，我们不知道它到底记了什么。

它突然用错语气，我们猜不到原因，它把两个项目混在一起，我们也找不到是哪条记忆串了。

PilotDeck 至少把这件事摊开了，Project Memory 记项目目标和进度，Feedback Memory 记我们的偏好和修改意见，错了可以改，乱了可以删，Dream 整理坏了还能回滚，甚至我们还可以设置一些 Always On 的一些任务流便于反复执行。

多 Agent 同时跑，听起来很爽，但如果每一步都烧最贵的模型，很快就不爽了。

PilotDeck 的做法是按任务难度分配模型。

设置里可以配不同模型供应商和模型能力，轻任务用便宜模型，关键判断用强模型。

更重要的是，成本按 WorkSpace 看得见。我们不是月底收到一张糊涂账，而是能看到哪个项目、哪个任务、哪类请求花了钱。

过去我用 AI，更多是在“问”：问它怎么写，问它怎么改，问它怎么看。

PilotDeck 把问题往前推了一步：现在我不只是问 AI，我在管理几个会持续工作的项目线程。

这也是它开源这件事让我觉得有非常意义的地方。

AI 工作台如果都变成封闭花园，文件、记忆、工作流、成本数据都会被锁在别人的平台里。

PilotDeck 开源之后，个人可以自己试，团队也可以自己部署。

地址是：https://github.com/OpenBMB/PilotDeck

官网地址：https://pilotdeck.openbmb.cn/

项目经验、文件、偏好、报告风格和 Skill，都可以留在自己的系统里。

我们不一定要亲手做每一步，但我们知道每一步在哪发生。

一个人，终于有点像在带一支智能体团队了。
