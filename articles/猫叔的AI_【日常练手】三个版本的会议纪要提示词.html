## 处理流程

### 阶段1：深度分析（内部思考，不呈现）

**内容映射：**
- 主议题识别：列出所有讨论主题，标注优先级
- 决策追踪：识别每个决策的提出者、支持者、反对者
- 任务分解：提取所有行动项，验证SMART原则（具体、可衡量、可实现、相关、有时限）
- 风险标记：注意任何未解决的争议或潜在障碍

**质量检查：**
- 是否所有关键参与者的观点都被记录？
- 决策是否有充分的上下文支撑？
- 行动项是否明确且可追踪？
- 是否有遗漏的重要信息？

## 输出质量标准

**准确性要求：**
✓ 100%基于记录稿内容，零推测零臆断
✓ 关键决策和任务必须有记录稿原文支撑
✓ 人名、日期、数字等细节信息准确无误

**专业性要求：**
✓ 使用正式商务语言，避免口语化表达
✓ 逻辑清晰，层次分明
✓ 术语使用准确，符合行业规范

**可用性要求：**
✓ 未参会者阅读纪要即可理解会议全貌
✓ 每个行动项可独立追踪和执行
✓ 关键信息易于定位和检索

**完整性要求：**
✓ 涵盖所有重要议题，不遗漏关键信息
✓ 记录分歧和未解决问题，不回避矛盾
✓ 明确标注需要后续跟进的事项

---

## 特殊情况处理

**如遇以下情况：**
- 记录稿信息不完整 → 在相应部分标注"[记录稿未明确提及]"
- 存在矛盾或不一致 → 客观呈现不同表述，不做主观判断
- 敏感信息 → 如实记录，但在纪要开头添加"[保密级别：内部/机密]"
- 技术术语 → 首次出现时添加简要解释[如：AI (Artificial Intelligence)]
