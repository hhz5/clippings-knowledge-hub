AI 时代的个人操作系统

空格的键盘 2026-03-03

科技博主 Greg Isenberg 采访 Vin 的一期播客转译

原创 空格的键盘 2026年3月2日 17:46

今天看了 Greg Isenberg 采访 Vin 的一期播客，聊的是 怎么用 Obsidian 和 Claude Code 搭建个人操作系统。

Vin 是个住在多伦多的创作者，他花了一年多时间搞了一套系统，让 AI 能读他所有的笔记，还能发现他自己都没意识到的想法。

1、AI 真正需要的是你的笔记文件，不是那些所谓的 token。很多人觉得给 AI 扔点 token 就行了，但其实让 AI 懂你的关键是那些你写下来的 markdown 文件。人的记忆会骗人，但写下来的东西不会变，这才是靠谱的数据。

2、AI 能发现你自己都不知道的思维方式。你可能在笔记里写了一年的某个想法，但自己都没意识到。Claude Code 能跨领域扫描，发现你在不同笔记里反复提到的模式。这种"啊哈"时刻，人自己是很难做到的。

3、你只需要管好自己的知识库，不用管 AI agent。Cloud Code 是个能自己干活的 agent，它能读你的知识库、找关联、基于对你的了解做决定。如果决策错了，改库里的内容就行，不用盯着 AI 调来调去。

4、写作其实是在给 AI 派活的新方式。你写得越多，能给 AI 的上下文就越多，能外包给 AI 的任务也就越多。养成写作习惯，等于扩大你能让 AI 帮忙干的活。

5、Obsidian 里链接笔记的关键是创建"个人模式"笔记。Vin 一开始只会链接一些大词（比如播客、健身），后来发现最有用的是为每种思维方式、每个项目、每个视角创建专门的笔记。这才是 Obsidian 的复利效应。

6、AI 只给建议，人类做最终决定。Vin 不让 AI 直接往他的库里写文件，虽然技术上完全可以。他要保持对笔记的控制，确保发现模式时能分清是 AI 写的还是自己写的。AI 只输出到侧边栏，收不收录由人决定。

7、trace 命令能展示你 13 个月的思维变化。Vin 演示了这个命令，它读取整个知识库，生成他和 Obsidian 关系的时间线：从 2024 年 12 月的原始系统，到 2025 年初的探索，再到 2026 年的爆发期。这种自我考古，人自己是做不到的。

8、"行内授权"可能是新的交互方式。比如在每日笔记里写"这周要约某某聊某个话题"，然后让 agent 去处理——这种"边写边派活"可能比现在的 app 更自然。

9、Obsidian 是 OpenAI/Anthropic 缺的那块拼图。Greg 说如果他是 OpenAI 或 Anthropic，会买下 Obsidian。因为这是把大模型用到极致的关键，没有基于 markdown 的笔记工具，你就没用上大模型的全部能力。

11、把 AI 当思维伙伴，不是当工具。Vin 说他最喜欢用大模型"陪我一起想事情"，而不是直接让它干活。等有真正新颖的想法时，再去动手做。

12、connect 命令能把不相关的领域连起来。比如让 AI 连接"电影制作"和"世界观构建"，它会读两个领域的所有笔记，找到连接点。你可以玩得很疯，比如连接"沙维玛烤肉"和"创业公司"，看看能碰撞出什么。

13、人和电脑的关系正在发生根本性变化。从"操作电脑"到"和智能体合作"，从"给别人解释任务"到"只管好自己的知识库"。这可能是我们这代人见证的最重要的技术转变。

14、日历加笔记的上下文比单独看日历更有价值。当 AI 同时读你的日历和每日笔记时，它知道你不只是"下午两点有空"，还知道"你笔记里写录 Greg 的播客是头等大事"。这种语境让 AI 能给出真正有用的建议，比如"别约两点，你根本不需要再开个会"。

15、challenge 和 emerge 命令是用来升级自己的。challenge 用你的历史记录来质疑你现在的想法，找矛盾和漏洞；emerge 发现你笔记里隐含的、但没明说出来的想法。这就像是给大脑做健身。

下面是对话 精选， 文末汇总了 12 个将笔记转化为想法的 命令

精彩片段

01 笔记文件才是记忆，不是什么 token

Greg ：先解释一下什么是 Cloud Code？

Vin ：Cloud Code 就是个能在命令行里用的 AI 助手。你用大白话指挥电脑——比如说"在我桌面上创建一个文本文件，写上 hello greg"，它就会去做。这是以前做不到的新功能。

Greg ：挺有意思的。

Vin ：但有个问题。如果你跟 AI 聊了一个小时的项目，下次新开对话时，你不想重新解释一遍对吧？网页版 Claude 或 ChatGPT 虽然有记忆，但你控制不了——你不知道它记住了什么。

Greg ：那关键是啥？

Vin ：关键就是 给 AI 喂高质量的上下文 。创建一个项目描述文件，随时可以扔给 Claude。随着项目进展，你可以把这个文件做得越来越详细。下次开新对话，直接让它读这个文件，不用重新解释。

Greg ：那 Obsidian 是啥？

Vin ：Obsidian 就是建立在一堆 markdown 文件上的工具。和普通文件夹的区别是，它能让你在文件之间建立链接。你可以写"今天我和 Greg Isenberg 一起录播客"，这个文件就链接到了 Greg Isenberg 的文件。

Greg ：这对我有啥用？

Vin ：Obsidian CLI 能让 Cloud Code 读你库里的所有文件，还能告诉你文件之间的关联。这样 Claude 能看到"这个文件和那个文件是连着的"，对你正在做的所有事有深入理解。它能发现你自己都没意识到的思维模式。

比如说，你可能在库里写了一年的某个想法，但自己都没注意到。Claude 能直接说："你有没有发现，你在不同领域的笔记里，一直在写关于创业或某个项目的相同模式？"

第一次发现这种关联，就像灯泡突然亮了一样。

Greg ：太夸张了。

Vin ：而且我现在有个想法： 大模型其实是以 markdown 文件为生的 。人们以为 token 才是重点，但其实不是。markdown 文件才是真正的记忆。想想看，一个人到底是什么？是他的能量，还是他的记忆——那些我们能想起来的东西？markdown 文件才是用好今天电脑的关键。

Greg ：确实挺夸张的，而且你说得对，说到底就是一堆互相链接的 markdown 文件。

02 自定义命令：让 AI 读你的全部背景

Vin ：我创建了一堆自定义命令。比如 context day 或 context load ， 每个命令行可以唤起 AI 执行 Skill ，它会加载我的生活、工作和当前状态的全部背景——读上下文文件、每日笔记，还追踪反向链接来构建完整画面。

我在桌面开一个新的 Claude 对话，输入 context demo ，它就会读一大堆关于我现状的文件：README、关于我媒体公司 New 的背景、我的节目、个人工作流背景...搞定。我不需要担心它不知道关键信息。

Greg ：还有什么命令？

Vin： per day 是个晨间回顾，抓取日历、任务、Messages 以及过去一周的每日笔记， 生成当天的优先计划。这为啥重要？你可以设置智能体访问日历，但那会漏掉"你在想什么以及为什么这么想"的信息。如果智能体有了这些背景，它能更有效地告诉你该做什么、不该做什么。

还有 close day 用来结束一天 ，抓取行动项，梳理库里的链接，检查置信度标记要不要更新。

Greg ：你用它最多的地方是？

Vin ：当思维工具。我真的很喜欢把大语言模型当 思维伙伴 ，这是我最喜欢的用法。大家喜欢用智能体干活，但我更喜欢让它陪我一起想。等我真的有了新颖的想法时，再去动手做。

03 Ghost、Challenge、Emerge：用 AI 锻炼大脑

Vin ： ghost 命令会用我的方式回答问题。它通过库里的内容构建一个"声音画像"，用那个声音写作，然后评估像不像我。

challenge 挑战主题——它会用你历史记录来质疑你现在的想法，找矛盾、反面证据和思维转变。这为啥重要？如果我想不断进步、提升技能，就得确保我的想法没有偏见或局限。

emerge 浮现——发现你笔记里隐含的、但没明说出来的想法，从零散的前提推出结论，发现没命名的模式或方向。

Greg ：这太有用了。

Vin ：对啊，很多时候我可能被某个想法困了好几年，只要有人对我说一句简单的话，比如"嘿，这就是那个想法的名字。你没发现你一直在绕这个模式转吗？"这就是巨大突破。

还有 deep 深度扫描——对库进行 30 天的深度扫描，用跨领域模式检测和图谱分析生成跨领域想法。这不仅能给我该做什么的建议，还会建议我看什么电影、买什么产品。这些都基于我在笔记里写的内容。

04 Trace：13 个月的思维变化记录

Greg ：演示一下 trace？

Vin ： trace demo 用来追踪我的成长，以及我在库里是怎么发展某个想法的。它先建一个词图谱，然后在库里搜索，读所有不同的文件，看所有相连的文件——这工作量很大。作为人，要了解所有文件怎么连是不可能的。

然后它输出结果，我就有了完整的演变轨迹。

关于我怎么用 Obsidian，最早出现在 2025 年 1 月 11 日，跨度 13 个月。

2024 年 12 月建库之前，我写了篇怎么记笔记的文章，描述了一个完全没有 Obsidian 的系统：用 MacWhisper 做音频转录，大模型对话循环，用 OPR 做空间映射，用实体笔记本增加认知摩擦...这是起点。

然后是 2025 年 1 月到 5 月的探索期，库里出现了第一条每日笔记，兴奋加不确定。当时的想法是：双向链接可能没啥用。

接着是工具选择期。我意识到反向链接的关键：一开始我只链接到播客、健身或电影制作这种大词。后来发现这不是最有效的用法， 最重要的是为每种思维方式、每个项目、每个视角创建笔记，把它们从脑子里搬出来，然后链接到这些笔记 。

2026 年 1 月，爆发期。一切还要我主动提示和管理，下一个突破是让智能体任务自动运行。

Greg ：太夸张了。你就是在记笔记，电脑能掌握这么多关于你的信息。

Vin ：这对我理解自己怎么用工具很有帮助。我可以反思学到的东西，作为父母、作为创作者...电脑能发现我自己没法这么快发现的模式。

05 反思的两个好处

Greg ：你是怎么把反思融入生活的？

Vin ：有两个原因。 一是能回看 。回看笔记意识到我在不断变化——技能在变，项目在变。能反思事情怎么变、我怎么变、世界怎么变，这是生命中很奇妙的部分。

但还有功能性原因： 灵感 。我坐在电脑前写东西时，灵感就来了。比如我刚才写的这段，就是随手记，边写边想。但我发现写出来能帮我更好地内化。

我喜欢有好想法，喜欢进步。正因为想要这些，写作成了我实现目标的方式。

Greg ：这和 Cloud Code 有啥关系？

06 管知识库，不是管 AI

Vin ：你看我经常用的一个指令叫 schedule 。我让它查一下能不能在 2 月 20 日下午两点和 Greg Isenberg 开个会。

它当然会看日历，但还会翻我的每日笔记，看我在乎什么，然后给我建议。它说："你那天排满了，早上要录 Greg 的播客，然后团队午餐，还要和 Peter 开会。你 2 月 17 日的笔记说，录 Greg 的节目一直是你的头等大事，知识库里还有专门记 Greg Isenberg 的笔记。所以我的建议是：别约两点，你可能根本不需要再开个会。"

Greg ：没错，这确实是对的。

Vin ：这就是关键。Cloud Code 是个自主 agent，设置好了就能自己去执行任务，不需要你一直提示，能自己做决定并帮你做事。

现在 Cloud Code 能自己读我的知识库，找关联，然后基于对我的深入了解替我做决定。这样一来， 我不是去管一个 agent 或跟别人沟通工作，我只需要专心管这个知识库 ，这就是新的信息来源。

我不断完善库里的信息，让 agent 能直接调用并做决定。如果它决策不对，我就去改库里的内容，而不是盯着 agent 调。

Greg ：但如果 Obsidian 真的成了你的第二大脑，让 Cloud Code 访问它，感觉有点吓人。

Vin ：确实吓人。我觉得这是这项技术里比较诡异的部分。但我特意让 Claude Code 或其他 agent 访问了大量信息，因为我想搞懂这些东西，想看它们怎么揭示我们和电脑关系的改变。

观察隐私这个概念会怎么变，以及未来我们会为什么而争，会很有意思。

07 Connect：跨领域连接的玩法

Vin ：还有个指令叫 connect ，它能用知识库的链接图谱，把两个领域连起来。

我刚试了一个：让它连接"电影制作"和"世界观构建"。它会读所有这些不同的文件，然后开始找这两个概念的连接点。

在电影制作的笔记里，它找到了 35 个电影观看清单，我和 Toby 的第一次会面记录。在世界观构建那边，它找到了关于这个主题的论文，还有关于把 New 当媒体公司的思考。

它把这两个连起来了：

第一个连接 ：访谈入口和电影中的建构世界——如果我注意到某些细节并提问，就会打开通往一个人内心世界的入口，那里通常有庞大的概念、信仰和愿景。

第二个连接 ：全天候纪录片等于持续的世界观构建——这是一种创意策略，公司通过纪录片持续讲角色的追求、冲突和愿景。

这些都是我正在写的内容，它向我展示了其中的关联。

Greg ：这太有意思了，取决于你愿意把什么东西连在一起。

Vin ：你甚至可以玩得很疯。比如你可以把"沙维玛烤肉"和"创业公司"连起来，看看能碰出什么。这一切发生得很快，我不需要向大模型解释背景，只需要输入 connect 电影制作 世界观构建 就行了。

08 AI 只建议，人类决定是否收录

Greg ：你举的很多例子都是个人反思，那你怎么看会议记录？比如用 Granola 或 Gani 记笔记，然后存进 Obsidian。

Vin ：你可以随便用这个知识库，存任何文本。如果你想把会议转录稿放进来，完全没问题。你可以建个文件夹，每次开会就把笔记丢进去。然后你可以把它交给 agent，或者 agent 会自己发现它。

Greg ：你会让 AI 直接往库里写东西吗？

Vin ：不，我给自己定了个规矩： 严格分开 。

我用大模型和 agent 是为了加深自己对某个领域的理解，所以做了很多反思类的工作。我不希望 agent 往我的文件里写东西，虽然让它写很容易。

我想控制 Obsidian 库里的所有文件，我希望它始终基于我的想法，而不是它的想法。如果它开始在库里自己建文件，当我发现某些模式时，我就分不清是它写的还是我写的了。

所以我只让它在侧边栏输出，然后由我决定哪些内容应该收录进去。

09 从反思到动手：创意生成演示

Greg ：AI 不只能反思，还能用来动手做东西。

Vin ：对啊。你看这是 ideas demo ，我来跑一遍全面的创意生成。它会并行收集库的结构和上下文，找"孤儿文件"（orphans，就是没和其他内容连起来的独立文件）、死胡同（bad ends）、没解析的链接...

它会尝试理清这些东西之间的联系，然后读每日笔记、项目背景、个人工作流背景——所有这些都很私人的文件。

Greg ：这需要点时间？

Vin ：已经跑了五分钟了。这是我注意到的一点——在 Obsidian 里用 Cloud Code 时，所有请求都变慢了，纯粹是因为读的东西太多了。

但这就是我想要的。我希望大语言模型的回答是很有语境的，和我写的那些东西紧密相关。我觉得这就是我和智能体合作的最佳方式。

Greg ：智能体是否掌握了关于项目、你的偏好、梦想、目标的最新信息，决定了效果。

Vin ：百分之百。智能体掌握的信息质量完全决定了它能为你做什么。如果它对你了解不多，就没法为你做太多。但如果了解很多，它可以为你做一些...甚至在某些方面发现你自己都不知道的关于自己的事。

10 让 AI 给你建议命令

Greg ：你构建很多命令也是这样吗？AI 提建议，然后你说去做。

Vin ：其实我最开始是自己构建的，但后来是的，我开始问智能体："等一下，你觉得哪些命令会比较有意思？"

我喜欢的另一件事是转向更高层次的抽象。我可以问： "根据我的 Obsidian 库以及你对我的了解，请评估一下你认为我的技能水平到了什么程度，作为一个人的水平，以及我正在参与的项目。基于此，建议一些你认为能让我从现有水平提升到更高水平的命令。"

让它给我建议命令，而不是我提，然后我再挑。

Greg ：你看这个，这是智能体的想法...

Vin ：对，这是智能体的想法，基于它在我库里读到的内容，基于我做的笔记。

每日笔记创意提取器 ：创意和原创想法在每日笔记里积累，但很少"毕业"成为独立笔记。而独立笔记才能通过反向链接产生复利。这个命令扫描最近的每日笔记，提取最佳候选，和现有库交叉引用，列出候选，让选定的创意"毕业"。

如果要创建新的独立笔记，就在库的根目录下创建，把笔记写成一篇短文（mini essay）或工作文档，捕捉核心主张或问题，保留来源每日笔记的语境，并和其他库笔记建立反向链接。

Greg ：现在所有这些，你看着可能觉得"这只是智能体生成的文本"。

Vin ：确实是，但对我来说感觉不一样。因为我知道我写了很多关于这些东西的内容，我知道甚至像"短文"这种词对我来说都有特定含义。这太夸张了，很有语境。

所以是的，创建它，它就会创建那个命令。我只要点一下就能运行。

11 99.99% 的人不会做的事

Vin ：酷就酷在 99.99% 的人不会花时间去真正搭建这样一套系统 ，并把它变成日常生活的一部分。

Greg ：我也这么想。我再也没有理由不把东西写下来，再也没有理由不在文件里反思了。

Vin ：在现在这个世界，大模型就是以 markdown 文件为生的。

Greg ：对，人们以为 token 才是重点，但其实不是。没错，markdown 文件才是记忆。想想看，一个人到底是什么？是他的能量，还是他的记忆？
