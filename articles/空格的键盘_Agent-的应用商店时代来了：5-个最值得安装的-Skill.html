最近几个月明显感觉到，Skill 这件事开始变得越来越规范了。

一开始它还像是大家各写各的提示词，放在各自仓库里，能用就行。

现在腾讯、小红书还有各家大模型 厂商都推出了各自的 Agent 应用和 Skill 商店。

用户可以上传 Skill，官方可以推荐。

这个感觉很像以前安卓手机刚起来的时候。到处都是 APK、应用市场：豌豆荚、应用宝。

但 Skill 和 App 最大的不同是门槛低很多。App 至少要写代码、做界面、打包、适配。

Skill 很多时候就是一个 SKILL.md ，再加一点脚本和参考文档。一个人把自己长期形成的工作方法写下来，就能变成 Agent 可以复用的能力。

之前我推荐过很多有趣的 Skill，比如 PM 相关的 pm-Skill，还有做视频生成的 HyperFrames。

这次一次性整理各个 Skill 平台上 5 个最火的 Skill。5 个仓库累计 star 接近 30 万。

1 last30days

最想推荐的的是 last30days。

这个 Skill 很巧妙，它解决的是一个非常现实的问题：很多问题不适合只让模型回答或只搜网页，得去看社交媒体。

比如最近 Skill 很火，光搜网页只能看到官方文档、博客、GitHub 仓库。但真正有意思的东西在 Reddit、X、GitHub issue 这些地方。

大家在讨论什么，吐槽什么，这些才是热度本身。

last30days 把过去 30 天里多个平台的讨论拉到一起，再让 Agent 综合判断。

传统搜索是在找"页面"。last30days 是在找"社交人群反应"。

这个设计是逼 AI 去真实世界里捞证据。它把社交媒体这种很散的信息，整理成一个可以复用的研究流程。

我最喜欢它的一点是，它很清楚模型容易偷懒。

所以它的 SKILL.md 写得非常硬核：必须跑引擎，不能只靠 WebSearch，不能自己编标题，不能把原始证据块直接倒给用户，引用要有链接，输出要有固定结构。

越复杂的 Skill，越不能只写"请认真调研"。真正有用的 Skill，要把模型常犯的错提前堵住。

2 Agent Reach

另一个和搜索、社媒、互联网访问相关的是 Agent Reach。

如果说 last30days 是把社交媒体变成研究引擎，那 Agent Reach 更像是给 Agent 装眼睛。

它是国内开发者做的，所以对中文互联网更友好。除了网页、GitHub、YouTube、Reddit、Twitter，也考虑了 B站、小红书、雪球、小宇宙这些平台。

中文语境下，很多真实消费决策、产品口碑、生活方式讨论，都发生在小红书、B站这些地方。

它甚至可以把小宇宙播客音频转文字。

Agent Reach 的使用方式很简单，安装

帮我安装 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md

它最有意思的设计是，用路由器的方式来搜不同站点的资源。网页走 Jina Reader，GitHub 走 gh，YouTube 走 yt-dlp，搜索走 Exa，B站走 bili-cli，小红书可以走 OpenCLI 或 MCP。

互联网平台不是稳定 API。今天能用的方式，明天可能被风控。

这个 Skill 没有执着于"我自己实现所有能力"。它做的是选型、安装、体检、路由。一个好的 Agent 基础设施，很多时候不该重复造轮子，而应该知道哪个轮子现在还能跑。

3 Matt Pocock Skills

第三个是 mattpocock/skills。

这个仓库 star 非常夸张，已经超过 14 万star。它的定位也很直接：Skills for Real Engineers（硬核工程师的进阶技能）。

我看这个仓库时最明显的感觉是，它是在教 Agent 像一个靠谱工程师一样工作。

npx skills@latest add mattpocock/skills

里面有好多个命令来执行 Skills。

/grill-with-docs ，用来在开工前不停追问需求，同时沉淀项目术语、ADR 和上下文文档。

有 /diagnosing-bugs ，要求先建立一个能复现 bug 的反馈回路，再开始猜原因。

还有 /improve-codebase-architecture ，会扫描代码库，找模块设计里变浅、变乱、变难测的地方，生成架构报告。

这和很多 coding agent 的使用方式刚好相反。

很多人用 AI 写代码，是直接丢一句"帮我实现这个功能"。模型很快写完，看起来很爽，但后面经常变成一团泥。需求没对齐，测试没跟上，bug 靠猜，架构越改越碎。

Matt 这套 Skill 解决的是工程规则，就像打造一个团队一样来管理 Agent 开发大型项目。

真实应用开发很难，不能把过程全交给一个黑盒流程。

这个设计很值得学。好的工程 Skill，应该让 Agent 慢下来，先问清楚，先建立反馈，先确认接口，先写测试，再动手。

4 Taste Skill

第四个是 Taste Skill。

这个 Skill 解决的是另一个常见痛点：AI 写出来的代码或内容太有 AI 味。

紫蓝渐变、居中大标题、三张功能卡片、玻璃拟态、圆角卡片、没完没了的微动效。这些不是不会写代码的问题，是审美默认值的问题。

Taste Skill 做的事，就是给 AI 一套审美校准系统。

它会要求 Agent 先判断页面类型：这是 B2B SaaS、作品集，还是公共服务页面。再判断用户要的气质：克制、实验、高级消费品、Linear 风/

然后它会设置几个旋钮，比如设计变化度、动效强度、视觉密度。

它把"审美"这种很虚的东西，拆成了 Agent 能执行的参数。

Taste Skill 改 AI 的默认坏习惯。

模型的能力够了，但默认值太俗。Taste Skill 做的就是把这些默认值一条条拧回来。不要默认紫色渐变，不要默认 Inter 加深色背景，不要默认三卡片布局，不要默认所有东西都像 SaaS 模板。

这种 Skill 很适合所有创作类任务。写作、设计、视频、PPT、品牌文案，都需要类似的"反默认值系统"。因为 AI 最容易生成的是平均值，而好作品通常要远离平均值。

安装方式

npx skills add https://github.com/Leonxlnx/taste-skill

5 Anthropic Cybersecurity Skills

最后是 Anthropic Cybersecurity Skills。

这个项目和前面几个不太一样。前面几个更像工具或流程，这个更像一个大型专业知识库。

它把网络安全领域拆成几百个 Skill，覆盖云安全、威胁狩猎、恶意软件分析、数字取证、SOC、IAM、容器安全、红队、渗透测试、漏洞管理这些方向。

它解决的问题也很清楚：AI 可以知道很多安全术语，但不一定知道专业人员真实工作时怎么走流程。

这个项目最值得看的地方，是它的组织方式。

每个 Skill 都有 frontmatter，它是用来给 Agent 快速扫描。这就是现在 Skill 设计里越来越重要的"渐进式披露"。先让 Agent 低成本知道有哪些能力，再按需加载细节。

这 5 个 Skill，总结一下：

  • last30days 把社交媒体变成研究能力。
  • Agent Reach 给 Agent 接上真实互联网。
  • Matt Pocock Skills 把工程纪律变成可重复流程。
  • Taste Skill 给 AI 补审美和反默认值。
  • Anthropic Cybersecurity Skills 把专家经验做成知识库。

最后

现在 Agent 也到了应用端蓬勃爆发的阶段，skill 接下来会更加规范统一和精准，数量也会由发散到收敛。

我会定期分享一些好用的 skill，以及设计理念给大家。

底座模型还会继续变强，但另一个更有意思的事情已经开始了：人类正在把自己的工具、经验、审美、工作流，拆成一个个 Skill，装到 Agent 身上。

未来一个垂类 Agent，可能不需要看模型本身，只要看它身上装了哪些技能。
