用了三个 Claude Skill 之后，我才明白为什么之前一直在瞎忙活（不写代码也很好用）

有了这些东西，CC更聪明，我能抽时间享受生活咯

原创 香君赛博淘金 2026年1月15日 01:39

Claude Code 我经常用，日常写代码、改 bug、做项目基本都靠它。但最近开始研究 Claude Skill，才发现之前的用法还是太"原始"了—— 光会用 Claude Code，跟真正把它用好，中间差着一个 Skill 的距离。

Skill 这东西，就是让 Claude 从"通才"变成"专才"。你不用每次都从零开始教它怎么干活，装上对应的 Skill，它就自动知道该按什么套路来。

研究了一圈之后，我想从 第一性原理 的角度，把这事儿讲清楚。

一、Skill 这东西，本质上是什么？

很多人以为 Skill 就是一段复杂的 Prompt，其实不完全对。

从技术角度看，Claude Skill 的核心是 动态上下文注入 。说人话就是：当你触发某个 Skill 的时候，系统会把一个 SKILL.md 文件里的完整指令"植入"到当前对话里，让 Claude 瞬间变成那个领域的专家。

这里边有个很精妙的设计叫 双层上下文 ：

  • 一层是你能看到的（显示"正在加载 xxx Skill"）
  • 一层是你看不到的（SKILL.md 里的完整工作流指令）

这就像给 Claude 装了一个可插拔的"专业大脑"。需要写代码的时候插上开发者大脑，需要整理文档的时候换上秘书大脑。 不是它变聪明了，是它知道该按什么套路干活了。

理解了这个，再去看那些神级 Skill，就能明白它们到底神在哪。

二、Superpowers：让 Claude 先问问题，再干活

Github地址：https://github.com/obra/superpowers

大家刚上手玩CC都是一个臭毛病，一上来就让 Claude 写代码。"帮我写个贪吃蛇游戏"，然后它就真给写了一个——用的技术栈我不熟悉，规则也不是我们想要的，基本等于白干。

Superpowers 解决的就是这个问题：它让 Claude 学会了"反问"。

装了这个 Skill 之后，你扔一个模糊的需求过去，它不会急着干活，而是像个产品经理一样反过来盘问你：

  • 用什么技术栈？
  • 面向什么用户？
  • 有没有特殊规则？
  • 要不要写测试？

它内置了 20 多个经过实战验证的子技能，包括 TDD 测试驱动开发、YAGNI 原则（不要过度设计）这些软件工程的最佳实践。 等它问完的时候，一份清晰的需求文档也就自动生成了。

我现在的用法是：有个复杂的 idea 不知道从哪下手的时候，先让它用问题轰炸我一遍。这个过程其实也是在帮我自己理清思路。

它自称"瑞士军刀"，一点都不夸张。

三、Planning with Files：给 AI 一个"烂笔头"

Github地址： https://github.com/OthmanAdi/planning-with-files

这是目前最火的 Skill，据说复刻了那个估值 20 亿美金的 Manus 的核心工作流。

它解决的问题很直接： AI 的上下文窗口有限，聊久了就忘事儿。

解决方案也很简单粗暴： 好记性不如烂笔头。

装了这个 Skill 之后，Claude 会自动在你的项目目录里创建几个 markdown 文件：

文件 作用
task_plan.md 任务清单，做完一个勾一个
step_plan.md 当前执行计划和思考过程
findings.md 过程中遇到的坑、新想法、查到的资料

关键在于，Claude 每做一步之前，都会先去读这几个文件，更新状态，然后再动手。

  • 以前： 你得提醒它"记得参考上面的 User 表哦"
  • 现在： 它自己会去翻文件，发现"哦，User 表已经建好了，我现在该写接口了"

这改变的不是 AI 的能力，是 AI 的 工作方式 。它从一个凭空瞎编的聊天机器人，变成了一个有工作日志、会自我管理的执行者。

我第一次看到 task_plan.md 里的任务被一个个自动勾选完成的时候，那种感觉就像——终于不用当保姆了。

四、NotebookLM Skill：给 Claude 接一个外部大脑

Github地址：https://github.com/PleasePrompto/notebooklm-skill

这个 Skill 解决的是另一个痛点： 知识库太大，喂不进去。

你手头有一堆 PDF、研报、技术文档，想让 Claude 基于这些资料出方案。但直接拖进聊天框，要么超长报错，要么它读得不仔细，给你胡说八道。

NotebookLM 本身是 Google 的产品，处理文档很强。这个 Skill 做的事情就是 把 Claude 和 NotebookLM 之间的墙打通了 。

具体玩法：

  1. 把资料扔进 NotebookLM 的笔记本
  2. Claude 直接去查询这个笔记本，获得带引用的回答
  3. 每个回答都有出处，不会瞎编

这相当于给 Claude 接了个"外部硬盘"。它的回答不再是从训练数据里瞎猜，而是从 你的知识库 里检索出来的，还能告诉你具体引用了哪份文档的哪一段。

注意：这个 Skill 只能在本地 Claude Code 里用，网页版跑不了（因为需要浏览器自动化）。

五、不写代码的人怎么用？

上面说的例子偏开发，但其实这三个 Skill 对不写代码的人一样好使。

Superpowers → 帮你把模糊想法问清楚

  • 写公众号：不知道从哪个角度切入，让它反问你目标读者是谁、想传达什么核心观点
  • 做活动策划/婚礼筹备：想法很模糊，让它问清楚预算、人数、风格偏好，问完方案就出来了
  • 创业 idea 验证：让它帮你问出商业模式、目标客户、和竞品的差异
  • 旅行规划：让它问你预算、时间、同行人、偏好，问完行程就能生成

Planning with Files → 帮你管理复杂项目进度

  • 写论文/书稿：分章节追踪进度，随手记录查到的资料和灵感
  • 装修房子：记录各房间进度、供应商联系方式、踩过的坑
  • 做副业/自媒体：追踪多平台内容发布、选题库、数据复盘
  • 考研/考证：学习进度管理，错题和重点整理

NotebookLM Skill → 让 AI 基于你的资料回答问题

  • 备考：把教材笔记扔进去，让它基于你的资料答疑解惑
  • 投资理财：把研报、财报扔进去，让它帮你做分析
  • 看病前准备：把体检报告、相关资料扔进去，帮你整理要问医生的问题
  • 签合同前：把合同扔进去，让它帮你挑出需要注意的条款

说白了，这三个 Skill 解决的是 想不清楚、记不住、资料太多 这三个通用痛点，跟你会不会写代码没关系。

六、为什么这比"提示词工程"更重要？

我之前也收藏了一堆"Claude 高效指令大全"，现在回头看，那些东西都太表面了。

这三个 Skill 代表的是一个更本质的方向： 从聊天走向智能体。

Skill 解决的问题 作用层
Superpowers 需求模糊 输入端
Planning with Files 过程遗忘 执行端
NotebookLM 知识瓶颈 资源端

当你把这三个工具组合起来，你会发现自己的角色变了——不再是费劲敲键盘的"提示词工程师"，而是看着 AI 自动跑任务、只负责最后验收的 项目管理者 。

行，就先聊到这儿。我接下来准备把 Planning with Files 好好玩一玩，看看能不能彻底告别手动整理文档的日子。

你们要是有什么好用的 Skill，评论区 cue 我，咱互相抄作业。
