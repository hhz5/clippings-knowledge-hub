前言

最近做了不少个人 Agent 定制咨询，来咨询的有产品、运营、营销、自由职业的。

对于 AI 工具的使用和理解各不相同，唯有的共同点是都用过豆包。

聊到 Agent 的时候，很多人就各有各的理解。

chatbot、LLM、Agent、skill、Prompt，这些概念交错起来。

让有些人误以为 chatbot 为代表的产品是 Agent、LLM 是 Agent。

但这些 AI 对话产品不像 Agent 那样可以操作你的电脑、文件、skill...

使用豆包，每次想让它干点什么，得手动传文件给它，得把背景从头交代一遍。它没有记忆，没有 Skill，也没办法主动操作电脑、浏览器、本地的任何工具。

Agent 不一样。

它能直接读电脑上的文件，调用工具，用 Skill 把一套工作流封装成一个动作交付出来。

举个最简单的例子。想做一份 PPT，基于本地写过的内容。常规流程是这样：

  • 选择内容
  • 确定风格
  • 输出成品

熟练之后，可以把这套流程做成一个 PPT 制作 Skill。

下次只要发一段内容，调用 Skill，PPT 就出来了。

再进一步，还可以让它定时执行。每天早上 8 点，主动扫描电脑上当天新增的笔记，扫描订阅的 RSS 源，自动生成当天的内容卡片、PPT 或者其他任何形式。

你睡着的时候它还在帮你干活，这才是 Agent。

1 我的主力是 codex 和 claude code。

Codex 用来做产品，写代码、做原型、跑工程；Claude Code 用来写内容，公众号、专栏、商单。

2 国产模型平替。

01 什么是 coding Agent

我看过比较清晰的一个定义：

模型（LLM）+ Harness 框架 = Agent

模型是大脑，Harness 是记忆和手脚。模型决定它有多聪明，Harness 决定怎么做事情。

按这个定义，市面上的 coding Agent 大概可以分成几类：

1）CLI 类（终端命令行）

特点是门槛高，得会用终端。但天花板也最高，可以接任意模型 API、装 Skill、操作整个文件系统。

  • Claude Code：Anthropic 出品，写作、长文分析、 代码输出的天花板
  • Codex CLI：OpenAI 出品，工程能力强，做产品首选
  • Gemini CLI：Google 出品，多模态强，配合海量上下文
  • Kimi CLI / 千问 CLI：国内厂商跟进版本

2）桌面客户端类

开箱即用，下载、登录、订阅会员就能跑。比 CLI 友好太多，深度定制能力弱一些。

  • Claude Cowork（Claude Desktop）：Anthropic 官方桌面端
  • Codex App：OpenAI 的桌面端
  • Minimax Agent、Skywork Desktop：国产桌面端

3）IDE / 代码编辑器类

编辑器加 AI 的结合，适合一边浏览代码、文件，一边让 AI 改。

  • Cursor：基于 VS Code 改的 AI IDE，写代码神器
  • Trae：字节出品，国产 Cursor 平替
  • Antigravity：Google 出品，能白嫖一年 Gemini 额度
  • Codebuddy：腾讯出品

4）Agent 系统类

像一个一直活着的 Claude Code，不需要打开终端，可以对接即时通讯工具，如飞书、钉钉，发条消息它就去干活。局限性在于你看不到它在干嘛，以及经常会抽风，换了模型效果就变了。

  • OpenClaw（小龙虾）：开源 Agent 框架，可以接飞书、Telegram、Signal 等 IM
  • Hermes、Opencode：其他开源 Harness 框架

5）网页端

适合交付物标准化的任务，生成网站、PPT、报告这种。但深度上下文不行，订阅费一般都很贵。

  • Lovable、Figma Make、Notion AI、Manus：浏览器里直接用的 Agent

02 最推荐的入门客户端：Codex + Claude Code 桌面端

第一次接触 coding Agent，建议不要直接上 CLI。先用桌面端，把感觉建立起来。

我现在主要推荐两个：

  • Codex 桌面端：从chatgpt.com/codex下载，需要 ChatGPT Plus（$20/月）或 Pro（$200/月）
  • Claude Code 桌面端：从claude.ai下载，需要 Claude Pro（$20/月）或 Max 套餐

可以先用免费额度跑几天试试感觉，再决定要不要订阅。

注册和订阅这步，国内会卡一下，订阅支付、虚拟手机号、节点之类的。

搞不定就去咸鱼解决，别在这一步就耗掉热情了。

1）Codex 桌面端怎么用

下载完打开，界面很干净，重点关注几块：

1 项目文件夹

最关键的设置。要让 Codex 知道它能操作哪个文件夹。

我一般会指定一个项目目录，比如某个 obsidian 仓库，Codex 后面所有的读写都在这里发生。

2 模型选择

Codex 内部可以切模型，GPT-5.2、GPT-5.3 Codex、GPT-5.4 都行。

日常用默认就行，复杂任务切 Codex 专用模型。

3 安全策略

我自己的策略：日常项目设成自动执行所有命令，敏感项目（比如有线上凭据的）保持每次确认。

4 对话流、浏览器预览、终端

Codex 桌面端的强项是有内置浏览器和终端。

写完代码可以直接打开浏览器预览效果，跑命令也不用切窗口，所有动作在一个界面里完成。

5 Skill 和插件

Codex 也支持 Skill（原生叫 Custom Instructions / Tools），可以装第三方插件，也可以自己写。

可以下载我开源的 skill：github.com/zephyrwang6/myskill

插件能套codex 和第三方平台连接，比如 github、figma、gmail 的插件，会让你登录你的账号，后续 codex 就能获取你账号下的数据，推荐你可以安装这几个插件。

6 自动化

可以让它每天某个时间自动跑一段流程。比如每天早上自动扫描 GitHub 上的 issue，生成 daily summary。

2）实操：用 Codex 装一个 PPT Skill

来个最具体的练手场景。

打开 Codex，跟它说：

帮我作一个 HTML-PPT 的 Skill。流程是：1 我发一段文字内容；2 它问我要什么风格（极简 / 商务 / 活泼）；3 它用 pptx 库生成 .pptx 文件保存到桌面。

Codex 会：

1 创建一个 Skill 文件夹，比如~/.codex/skills/ppt-maker/

2 写一个 SKILL.md，定义触发词和执行流程

3 装好需要的依赖（python-pptx）

4 跑一次测试，确认能用

下次发 "帮我把下面这段内容做成商务风 PPT"，Codex 自动调用这个 Skill，几十秒后桌面上就多了一个 .pptx 文件。

3）Claude Code 桌面端

逻辑和 Codex 几乎一样，区别在于：

  • 模型用的是 Claude（Opus / Sonnet）
  • 写作、长文分析、复杂指令理解上比 Codex 强一档

两边各订一个会员，加起来 $40/月

如果只能选一个，看主要场景：

  • 主要做产品 / 写代码 → Codex
  • 主要写内容 / 做知识管理 → Claude Code

03 进阶：CLI 版本 Agent 下载和安装

桌面端用熟了之后，会感觉到它的天花板。

它没办法跑后台任务，没办法和 bash 工作流深度结合，没办法接任意模型 API。

这时候就该上 CLI 了。这里我只推荐 claude code CLI，也可以搭配国产模型 API。

mac 上打开 terminal，window 打开 powershell

在命令行输入下面，CLI 版本的下载也很简单，一行命令：

# Claude Code CLInpm install -g @anthropic-ai/claude-code

装完之后在终端里cd到项目目录，敲claude或codex，回车，就进入对话界面了。

CLI 的体验和桌面端最大的区别：它跑在真实的终端环境里。

它能直接读能直接执行任意 Bash、shell 命令、Git 操作、Docker 容器，能接入本地的任何脚本、工具、CLI。

可以学一些常用的快捷操作，比如 shift+TAB 切换模型，/调用命令。

对一个 AI 来说，能用终端约等于能操作整台电脑。

04 必备工具：CC switch

CLI 用熟之后，下一个问题就来了。

claude、oepnai 买的套餐 token 不够用怎么办？

这时候需要的是国产模型 API 做平替。

现在智谱、minimax、DeepSeek 最新旗舰模型做的都挺不错了，代码场景完全可以用他们，价格还便宜不少。

但手动切模型很麻烦。

今天想用 Claude Sonnet，明天想切 GLM 4.7，后天又想切回去。

CC Switch 可以做到一键切换。

下载地址：

一个图形化的 API 管理工具，专门管理 Claude Code、Codex CLI 等 Agent 的模型来源。在里面可以：

  • 注册多个模型供应商（Anthropic 官方、智谱、Minimax、Kimi、各种中转站）
  • 一键切换当前 Agent 使用的 API
  • 管理 API Key、统计用量
  • 顺便管理本地的 Skill 库

操作流程巨简单：

1 在主界面，选择 Agent 厂商，比如 Claude Code

2 选择模型 API 厂商，比如智谱

3 输入 API Key

4 保存，点启用

5 重新打开 Claude Code，已经在跑 GLM 了

切换一次大概 10 秒。

05 模型 API 是什么

插一段基础知识，因为很多人对 API 这个概念是模糊的。

模型 API，就是访问大模型的地址和钥匙。

每次和 Agent 发消息的时候，背后发生的事情大概是这样：

我 → Agent 客户端 → 模型 API 接口 → 大模型服务器 → 返回结果 → 显示出来

中间那个模型 API 接口，由三个核心参数定义：

1 API 地址（URL / Base URL）。访问到大模型的路径，比如https://api.DeepSeek.com

2 API Key。身份凭证，证明有权限用，证明费用从这个账户扣

3 模型名称（Model）。用这家厂商的哪个具体模型，比如claude-opus-4-7或glm-4.6

这三个是必填项。剩下还有些可选参数：流式输出、思考深度（thinking）、温度（temperature）、最大输出长度等等，平时不太需要动。

06 实操：在 Claude Code 里配置国产模型 API

来个手把手的例子。以智谱 GLM 4.7 为例，也是我自己主力的国产模型之一。

第一步：注册拿 Key

去open.bigmodel.cn用国内手机号注册，控制台里创建一个 API Key，复制保存。

智谱有个套餐叫 Coding 计划，最低档 49 元/月（国内各家价格都差不多），额度对个人用户来说基本用不完。开一个就够。

第二步：用 CC Switch 配置

打开 CC Switch：

1 选 Claude Code 作为目标 Agent

2 添加新供应商，填：

  • 名称：智谱 GLM
  • Base URL：https://open.bigmodel.cn/api/anthropic
  • API Key：刚才复制的那串
  • Model：glm-5.1

3 保存，点启用

第三步：验证

新开一个终端窗口（重要，旧窗口环境变量没刷新），敲claude，进入对话。

随便问一句：

你现在可以回答我问题吗？

回复成功，说明配置成功了。这里也能看到配置的模型名称和版本号。

同样的方式接 Minimax

Minimax 的 API 地址是https://api.minimax.chat/v1（OpenAI 兼容）或者它的 Anthropic 兼容地址。

我的 OpenClaw 后端就是接的 Minimax，单价低、并发额度大，特别适合跑批量任务，夜里采集 100 篇文章、批量生成 50 张图这种。

为什么国产模型也能接到 Claude Code 里

Claude 和 OpenAI 这两家，定义了行业里两套主流的 API 标准。

所有 Agent 客户端（Claude Code、Codex CLI、Cursor、OpenClaw 等）默认对接的就是这两套之一。

国产模型厂商为了让自家模型能被 Claude Code、Cursor 这些工具调用，干了一件事：给自家 API 套上 Anthropic 兼容或者 OpenAI 兼容的外壳。

比如智谱的 API，访问https://open.bigmodel.cn/api/anthropic是 Anthropic 兼容格式，

访问https://open.bigmodel.cn/api/paas/v4是 OpenAI 兼容格式。

DeepSeek、Kimi、Minimax、千问，全都一样。

所以可以这样组合：

  • Agent 还是 Claude Code（壳）
  • 模型换成 GLM 4.7（脑）
  • 体验流畅度几乎没变化，token 价格降到 1/10

07 Skill 的统一管理

讲完模型层，最后讲 Skill 。这是 coding Agent 真正的杀手锏。

1）Skill 是什么（一句话版本）

Skill = 写给 AI 的 SOP（工作标准说明书）

日常重复做的某一类任务，把流程拆出来、把要求写下来、把输入输出定义好，存成一个 SKILL.md 文件，丢到 Agent 能读到的目录里。一个 Skill 就成了。

下次用一句话触发，Agent 自动按 SOP 执行。

我做过 100 多个 Skill，覆盖：内容创作、产品经理、图片制作、数据分析等等。

每个 Skill 都是一个我曾经手动做过 N 遍的工作流。

2）三层架构：怎么让所有 Agent 共用同一套 Skill

只用 Claude Code 一家，Skill 放在~/.claude/skills/就行。

但我同时用 Claude Code、Codex、Cursor、OpenClaw，四个 Agent，不需要每个都维护一份

我用的是软链接加分类仓库的三层架构：

核心规则只有一条：永远改全局，再同步到分类仓库。

我自己的开源的 skill仓库是这样：

你直接复制下面仓库名就能访问或下载：https://github.com/zephyrwang6/仓库名

每周复盘的时候，我会让 Claude Code 自动扫描~/.claude/skills/有没有新增 Skill，然后归类、commit、push。一条命令的事。

3）Skill 怎么装

我自己做的 100 多个 Skill 已经开源了，仓库地址在我的 GitHub 主页。流程是：

1git clone到本地，帮我从https://github.com/zephyrwang6/myskill

2 复制需要的 Skill 文件夹到~/.claude/skills/下

3 重启 Agent，触发词一发就能用

也可以直接让 Claude Code 帮我装：

帮我从 https://github.com/zephyrwang6/myskill 仓库里下载 brand-article 这个 skill，安装到全局 skill 目录。

它会自动 clone、复制、确认 SKILL.md 格式正确。

1）Skill 怎么用

每个 Skill 的 SKILL.md 顶部都有一个 description 字段，定义了它什么时候被触发。

比如我写的 brand-article Skill，触发词是 "商单" "甲方文章" "品牌合作" "推广文章" "写商单"。

说话里带这些词，Agent 就会自动加载这个 Skill 的完整内容，按里面的流程走。

不需要记触发词，自然说就行。Anthropic 设计 Skill 的时候用的是渐进式披露原则，平时只加载 Skill 名字和描述，相关的时候才加载全文。

08 OpenClaw：让 Agent 一直活着

走到这一步，应该建立起一个习惯：遇事不决，先找 Agent。

查资料、下载互联网上的任意内容、做数据分析、整理文件夹、搜索电脑上的文件、做 PPT、做 Excel，再技术一点，OpenClaw 报错、终端命令行操作失败，都可以丢给 Agent 解决。它比互联网上任何教程都靠谱，因为它能直接看到我电脑的真实状态。

带着这个心态再来看 OpenClaw。

1）OpenClaw 是什么，能干什么

很多人问我："你怎么做到飞书发条消息它就在电脑上干活？"

答案就是 OpenClaw。

它是一个常驻后台的 Claude Code，前面挂了一个 IM 网关。

飞书里发条消息 → IM 网关接收 → 喂给 OpenClaw 后台 → 它操作电脑文件、调 API、跑脚本 → 把结果发回飞书。

我的 OpenClaw 配置：

  • 后端 Agent：OpenClaw（小龙虾）开源版本
  • 接入 IM：飞书机器人
  • 模型：Minimax（量大实惠）
  • 任务类型：每日采集、定时归档、文档同步、批量出图、夜间爬虫

它最大的价值是离开电脑也能用 Agent。出门在外，看到一个不错的网页内容，飞书里发一句 "把这个网页存到我的素材库 03 播客分类里"，OpenClaw 就在家里的 Mac 上把活干完。

但刚入门先别折腾 OpenClaw。它适合那些已经把 Claude Code + Skill 跑通、有大量重复自动化需求的进阶玩家。前 90% 的需求，Claude Code 桌面端加几个 Skill 已经够用了。

2）安装 OpenClaw

OpenClaw 是开源项目，去 GitHub 搜 OpenClaw 找到官方仓库。

安装这一步不用啃文档，直接把官方仓库 README 链接丢给 Claude Code，让它边读边装：

帮我在本地安装 OpenClaw。仓库地址是：https://github.com/.../openclaw我的系统是 macOS。装完跑一次自检，确认能正常启动。

Agent 会自己 clone 仓库、装依赖、写配置、跑启动命令。中间有报错就把报错贴回去让它改，比对着教程一行一行抄快十倍。

类似的开源 Agent 框架还有 hermes，可以了解一下，但不推荐用，文档和生态都比 OpenClaw 差一档。

3）给 OpenClaw 配置模型 API

OpenClaw 是开源框架，自带模型，跑起来必须接一个外部模型 API。

两条路：

一是用 CC Switch 配置，和前面给 Claude Code 配国产模型一个套路，选 OpenClaw 作为目标 Agent，添加供应商，填 URL 和 Key 就行。

二是直接让 Agent 帮我配。把模型厂商的文档链接和 Key 丢给 Claude Code：

我想在 OpenClaw 里接智谱 GLM 4.7 的 API。这是文档：https://open.bigmodel.cn/dev/api我的 Key 是 xxx请配置好，并跑一次测试确认能用。

Agent 自己读文档、写配置、改环境变量、跑测试。每家厂商的文档都不一样，智谱、Minimax、Kimi 的参数位置都不同，硬啃没必要。

我自己 OpenClaw 后端用的是 Minimax。OpenClaw 的特点是任务量大、跑得久（夜里采集、定时归档），单价低的国产模型最划算。Minimax 的并发额度也大，跑批量任务不容易卡。

09 总结：实操路线

上面基本讲完了所有你能用的到的 Agent，接下来就差动手实践了，

安装、注册、登录、订阅只是开始，当你让它为你制作你工作最常用的文档，用 Skill 让它在你休息的时候给你打工时，你就获取到了这个时代最大的复利，让 Agent 为你打工。

下面做了总结，一个全面的实践路线图

Stage 1：建立感觉（第 1 周）

  • 下载 Claude Code 桌面端 或 Codex 桌面端
  • 订阅 Pro 会员（搞不定就咸鱼）
  • 跟它聊一周，丢任意文件给它处理，感受它和豆包的区别

Stage 2：装第一个 Skill（第 2 周）

  • 安装网络上比较火的 skill
  • 找一个每天重复做的工作流
  • 让 Agent 帮我封装成 Skill
  • 用一句话触发，体验一下 "丢一句话出活" 的感觉

Stage 3：进阶 CLI（第 3 周）

  • 装 Claude Code CLI / Codex CLI
  • 把工作目录（比如 Obsidian 仓库）接入进去
  • 写一个 CLAUDE.md 把偏好和工作流定义清楚

Stage 4：模型路由（第 4 周）

  • 装 CC Switch
  • 注册一个国产模型（智谱、minimax）
  • 跑量任务全切到国产，主力套餐留给攻坚

Stage 5：自动化（第 2个月起）

  • 折腾 OpenClaw 或类似框架
  • 把高频自动化任务挪到后台
  • 让 Agent 在我睡觉的时候继续干活

10 最后

这篇比较入门，适合第一次接触 coding Agent 的人。

但讲完这些，也只是工具的使用方法。

工具用好的关键不是工具本身，是理念。

要让 AI 真正变成生产力工具，读文件、记偏好、按 SOP 干活、人不在的时候继续工作，需要的是 coding Agent。

coding Agent 的核心从来不是某一个工具。是模型、Harness、Skill 加上自己的上下文这四样东西。

把这一步走通之后，可以让它接着做别的事情。

怎么用 Agent 做知识管理， 做 vibe coding，每一个方向单独拎出来都是一篇长文。
