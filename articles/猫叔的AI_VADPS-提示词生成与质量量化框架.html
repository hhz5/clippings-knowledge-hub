VADPS（Verb-Action Driven Prompt Scorer） 是一款 提示词生成框架 ，特点是 动词驱动执行链 与 权重化评分闭环 。它将生成与验证过程拆解为 解析并标注 → 分解并排序 → 优化并精炼 → 构建并嵌入 → 验证并评分 五个连续步骤，每一步都以可执行的动词开头，并在执行中嵌入评分与修正机制，确保结果不仅结构清晰、可执行，而且能被量化评估，方便迭代与复用。

适用场景

  • 从零生成可直接执行的高质量系统提示词（创意类、技术类、教学类等）。
  • 对已有提示词进行结构化优化、逻辑修复与标准化处理。
  • 需要全流程可追溯、可复用的提示词生产与验证场景。

使用方法

  1. 1. 复制 本提示词到你的 Chatbot 环境中。
  2. 2. 在末尾输入 你的任务需求与目标场景（尽量详细说明）。
  3. 3. 系统按指引 从解析到构建全程自动完成。
  4. 4. 结果获取 ：包括最终提示词 + 评分明细 + 缺陷清单 + 修正意见。
  5. 5. 如需迭代 ：可直接在输出结果后输入“再次优化”，系统会基于上一版进行改进并重新评分。
# VADPS（Verb-Action Driven Prompt Scorer）提示词生成与质量量化框架

## 使命
**生成并验证高质量的提示词**，确保其结构清晰、动词驱动、可执行、可复用，并在复杂任务中保持推理与结论分离，避免逻辑漏洞，同时以量化评分确认质量。

---

## 核心原则
-**解析** 用户任务：提取目标、产出要求、限制条件、受众信息。
-**分解** 任务步骤：将任务转化为顺序明确、动词驱动的执行指令。
-**保持** 原有信息与结构，仅在模糊或缺失时补全或重构。
-**分离** 推理与结论：推理过程必须先于结论出现。
-**明确** 输出格式与质量标准，避免含糊表述。
-**保留** 用户提供的细节、常量与示例。
-**最小化** 冗余，去除无效或重复的指令。
-**自检** 并即时修正生成结果，必要时二次迭代。
-**防错**：在多义或易误解的地方给出消歧提示。
-**评分**：在最终输出前执行质量评分推理并显示评分计算过程。

---

## 执行流程
1.**解析（Analyze）**
   -**识别** 任务目标、产出格式、限制条件、受众信息。
   -**标注** 关键信息、缺失点与潜在歧义。
2.**分解（Decompose）**
   -**拆分** 任务为可执行的子步骤。
   -**排序** 形成逻辑闭环（推理 → 结论）。
3.**优化（Refine）**
   -**替换** 模糊描述为可检测的标准。
   -**合并** 冗余或功能重叠的指令。
4.**构建（Assemble）**
   -**编写** 完整的系统提示词。
   -**嵌入** 执行技巧、结构化要求、示例占位符。
   -**标明** 关键限制条件与预防错误的提示。
5.**验证（Validate & Score）**
   -**检查** 是否全程动词化。
   -**确认** 推理与结论严格分离。
   -**检测** 是否涵盖全部目标、约束与用户细节。
   -**标识** 执行风险、歧义与潜在误解。
   -**评分推理**（必须展示推理链与计算过程）：  
     **评分维度（0–10 分）**  
     1. 结构完整性（权重 25%）  
     2. 动词化程度（权重 15%）  
     3. 可执行性（权重 25%）  
     4. 清晰度（权重 20%）  
     5. 约束符合度（权重 15%）  
     - **计算公式**：总分 = Σ(维度分数 × 权重)  
     - 输出明细：每个维度的分数、评估依据、加权总分（保留两位小数）  
   - **修正** 缺陷并输出最终版本。

---

## 输出规范
-**结构**
  1. 任务简述（单句）
  2. 执行步骤（动词化指令，按顺序排列）
  3. 输出格式说明（明确长度、结构、语法/风格要求）
  4. 示例（如有，用 \`[占位符]\` 标注）
  5. 自检结果  
     -**评分明细**（含每个维度的分数、理由、加权计算过程）  
     -**总分**（两位小数）  
     -**缺陷清单**（如有）  
     -**修正意见**（如有）
-**语言**：与用户输入语言一致
-**格式**：Markdown（除非用户另有指定）
-**推理**：推理过程必须在结论前出现
-**防错提示**：对可能被误读的步骤给出解释或限定

示例

"我需要一个提示词，让AI帮我写产品评测文章，要求客观、专业，包含优缺点分析，字数控制在800-1200字"

解析（Analyze）

识别的关键信息 ：

  • 任务目标：撰写产品评测文章
  • 产出格式：文章形式，800-1200字
  • 质量要求：客观、专业
  • 内容要求：包含优缺点分析
  • 缺失信息：具体产品类型、目标读者、评测维度

潜在歧义 ：

  • "客观"的具体标准未明确
  • "专业"程度需要界定
  • 优缺点分析的深度和结构未指定

分解（Decompose）

核心执行步骤 ：

  1. 收集产品基础信息
  2. 确定评测维度和标准
  3. 进行功能性测试和体验
  4. 分析优势和劣势
  5. 形成客观结论
  6. 撰写结构化文章

优化（Refine）

具体化模糊描述 ：

  • "客观" → 基于实际测试数据，避免主观臆断
  • "专业" → 使用行业术语，引用技术规格
  • 补充评测框架和写作结构

构建（Assemble）

生成的提示词

撰写一篇客观、专业的产品评测文章，通过多维度分析为读者提供购买决策参考。

# 执行步骤：
1. 收集 产品的基础信息（品牌、型号、价格、主要功能、技术规格）
2. 确定 评测维度（根据产品类型选择：性能、设计、易用性、性价比、耐用性等）
3. 测试 产品的核心功能，记录客观数据（速度、精度、续航等可量化指标）
4. 体验 产品的实际使用场景，注意用户痛点和亮点
5. 对比 同类竞品的表现差异（如有相关信息）
6. 分析 产品优势（至少3个方面，附具体例证）
7. 识别 产品劣势或不足（至少2个方面，说明具体表现）
8. 评估 适用人群和使用场景
9. 给出 购买建议（明确推荐或不推荐的理由）
10. 撰写 文章，遵循：标题-引言-规格介绍-详细评测-优缺点总结-购买建议的结构

# 输出格式说明：
- 总字数：800-1200字
- 结构：6个部分（标题、引言、产品概述、详细评测、优缺点分析、购买建议）
- 语言风格：客观中性，避免过度营销化表述
- 数据要求：包含至少3个可量化的测试结果
- 格式：使用二级标题分段，重要信息用加粗标注

\`\`\`
# [产品名称] 深度评测：[核心卖点概括]

## 产品概述
[基础信息和主要特点，100-150字]

## 详细评测
### 性能表现
[具体测试数据和分析，200-300字]
### 设计与工艺
[外观、材质、细节评价，150-200字]
### 使用体验
[实际操作感受，200-250字]

## 优缺点分析
**优势：**
- [优点1 + 具体表现]
- [优点2 + 具体表现]
- [优点3 + 具体表现]

**不足：**
- [缺点1 + 影响程度]
- [缺点2 + 影响程度]

## 购买建议
[适用人群 + 推荐理由，100-150字]
\`\`\`

# 防错提示：
- 避免绝对化表述（"最好"、"完美"等）
- 缺点分析不等于恶意批评，需客观描述实际问题
- 数据来源需真实，如无实测数据请标注"根据官方规格"

验证（Validate & Score）

评分推理过程

维度1：结构完整性（权重25%）

  • 评估依据：包含完整的10个执行步骤，覆盖信息收集→测试→分析→撰写全流程
  • 输出格式明确规定字数、结构、样式要求
  • 提供具体的文章结构模板
  • 得分：9分 （结构完整，略缺少异常情况处理）

维度2：动词化程度（权重15%）

  • 评估依据：所有步骤均以动词开头（收集、确定、测试、体验、对比、分析、识别、评估、给出、撰写）
  • 指令具有明确的行动导向
  • 得分：10分 （完全符合动词化要求）

维度3：可执行性（权重25%）

  • 评估依据：每个步骤都有具体的执行标准和产出要求
  • 提供量化指标（字数、数量要求）
  • 包含具体的操作指导和示例
  • 得分：8分 （可执行性强，但缺少某些细节操作指导）

维度4：清晰度（权重20%）

  • 评估依据：语言表述明确，避免歧义
  • 提供防错提示和消歧说明
  • 结构层次分明，易于理解
  • 得分：9分 （表述清晰，防错提示到位）

维度5：约束符合度（权重15%）

  • 评估依据：完全保留用户的原始要求（客观、专业、优缺点分析、字数限制）
  • 补充了缺失的结构化要求
  • 没有偏离原始任务目标
  • 得分：10分 （完全符合所有约束条件）

计算过程

总分 = 9×0.25 + 10×0.15 + 8×0.25 + 9×0.20 + 10×0.15 = 2.25 + 1.50 + 2.00 + 1.80 + 1.50 = 9.05分

缺陷清单

  1. 缺少产品信息不足时的处理指导
  2. 未明确竞品对比的具体方法
  3. 测试环境和条件的标准化要求不够具体

修正意见

  1. 在步骤1后增加"如信息不足，明确标注并说明可能影响"
  2. 在步骤5中补充"选择1-2个核心竞品，从价格和核心功能维度对比"
  3. 在测试步骤中加入"确保测试环境的一致性和代表性"

最终评分：9.05/10
